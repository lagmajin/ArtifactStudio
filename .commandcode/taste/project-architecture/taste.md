# project-architecture
- For new functionality in `ArtifactPr`, prefer an internal/centralized event system architecture (the style used in `Artifact/`) rather than ad-hoc Qt signal-slot wiring between widgets. Surface components should publish events to a central bus/service that other layers subscribe to. Confidence: 0.60

- Adding a new ColorCorrection-style effect requires SIX registration surfaces, not two — the ones that are easy to miss are the CMake duplicates. Verified while bringing `ShadowHighlightEffect` from header-only stub to working (2026-09-26): ① `Artifact/include/Effects/ColorCorrection/XxxEffect.ixx` (declarations) ② `Artifact/src/Effects/ColorCorrection/XxxEffect.cppm` (impl) ③ `Artifact/cmake/ArtifactSources.cmake` cppm list ④ `Artifact/CMakeLists.txt` — which carries THREE separate lists: a main cppm list, a `.ixx` list, AND a dedicated module list for the `ArtifactEffectsColor` STATIC library whose entries are later `REMOVE_ITEM`'d out of the aggregate target; a file added to only one of the CMakeLists lists is not linked into the color library. ⑤ `Artifact/src/Service/ArtifactEffectService.cppm` — THREE spots: the `import XxxEffect;` block, a `createEffect` factory branch `if (effectId == …) return std::make_unique<XxxEffect>();`, and a `effects.push_back({EffectID("effect.colorcorrection.xxx"), "Display Name"})` row in `availableEffects()`. ⑥ `Artifact/src/Widgets/InspectorEffectCatalog.cppm` — the catalog entry carrying pipeline stage, id, display name, category, description, and search keywords. Effect-ID convention: `effect.colorcorrection.<lowercase>` (singular `colorcorrection`). Corollary: after a bulk registration edit, re-read the edited hunk — an anchor-based insert silently produced both a wrong indent and a 3-space variant that needed a follow-up fix. Confidence: 0.65

- Effect CPU/GPU implementation classes are named `XxxEffectCPUImpl` / `XxxEffectGPUImpl`, subclass `ArtifactEffectImplBase`, and override `applyCPU(const ImageF32x4RGBAWithCache& src, ImageF32x4RGBAWithCache& dst)`; they are installed in the effect constructor via `setCPUImpl(ArtifactCore::makeShared<XxxEffectCPUImpl>())` + `setComputeMode(ComputeMode::CPU_ONLY)` + `syncImpls()`. A `syncImpls()` body does `dynamic_cast<XxxEffectCPUImpl*>(cpuImpl().get())` and copies each stored value into the impl's public `xxx_` member. `ComputeMode::CPU_ONLY` is the honest declaration for a CPU-only effect (e.g. `LUTEffect.cppm:82`) — a statement of fact, not a defect to "fix". Property exposure is `std::vector<AbstractProperty> getProperties()` (siblings use `push_back` + an `addFloat` helper; a fixed-size `std::vector<AbstractProperty> props(10)` with `setName/setType/setValue/setDefaultValue/setHardRange` also compiles) plus `setPropertyValue(const UniString&, const QVariant&)` dispatching on `name.toQString()` with a `setCommonPropertyValue(key, value)` fallback. Setters clamp and guard with `std::isfinite` before calling `syncImpls()`. Pixel loops run under `Parallel::For(0, height, width * height, …)` and bail out early when every correction term is inactive. Confidence: 0.6

- When fixing a per-pixel hot path, the fix must not introduce per-pixel copies, saves, or restores of a processor object. Applied 2026-09-26: `ColorGrader::processPixel` was calling `wheelsProcessor_.processPixel()` twice, so the first attempt saved/copied the whole `ColorWheelsProcessor` around a temporary `levels()` injection to merge the passes; that was rejected mid-task as 「ホットパス違反かつ非効率」 and reverted. The accepted shape moves the state injection OUT of the per-pixel function and into the loop-setup function (`process()` sets `wheelsProcessor_.levels()` once; `processPixel` then applies each processor exactly once). Corollary from the same fix: when the hot function is `public` and cannot safely change contract, state the resulting invariant in a comment and flag the unverified assumption explicitly in the final report (e.g. 「`processPixel` を直接呼ぶ経路（`process()` 経由でない）が存在する場合、levels が未注入になります」) rather than hiding it. Confidence: 0.65

- Audit an `isDefault()` / `isUnchanged()`-style predicate against the FULL member set of the struct it guards, not just the members its author happened to reference. Found 2026-09-26 while fixing `ColorLevelsParams::applyLevels`: `isDefault()` checked only `inputBlack/inputWhite/outputBlack/outputWhite/gamma/linkRGB`, ignoring the per-channel `inputBlackR/G/B` and `inputWhiteR/G/B` members — so a levels config with `linkRGB == false` and non-default per-channel inputs was classified as default and silently skipped. Fixing only the `applyLevels` body would have left the defect live. Confidence: 0.6

- When a parameter struct gains a `linkRGB`-style boolean selecting between shared and per-channel values, that boolean becomes load-bearing: every consumer must implement BOTH branches. An implemented `linkRGB == true` branch whose `false` branch silently does nothing is the tell, and the declared-but-never-read per-channel members are the evidence the false branch was never written. Confidence: 0.60

- A viewport "display-only" post-process must not write into the surface that readback consumers observe. In `CompositionRenderController::finalizeGpuRenderToViewport` (ArtifactCompositionRenderController.cppm:12669) the returned `finalPresentSRV` is assigned to `lastPresentedReadbackSRV_` at :12778 and is then read by the color sampler, the Color Science/Scopes panel, the magnifier overlay and the RAM preview readback — so a display transform written there silently changes sampled values and violates the requirement. Correct shape: run the effect into `renderPipeline.tempUAV()` and swap only at the final `presentationSRV` selection, leaving `finalPresentSRV` / `lastPresentedReadbackSRV_` untouched. Corollaries established 2026-09-26: restrict the stage to the `Color` display mode so it can never collide with the AOV/channel-display pass that also writes `tempUAV`; pick defaults that are an exact identity (gain 0 stops → `exp2(0)=1`, gamma 1 → `pow(c,1)=c`, saturation 1 → `lerp(luma,c,1)=c`) so shipping the stage enabled changes nothing; pass alpha through untouched because the color sampler reads it; guard against src==dst aliasing; allocate the executor/PSO and the small constant buffer once at init and only map/memcpy per frame; and fail soft (`qWarning` + present the unexposed surface) when the PSO fails to build. Future viewer post-processes (P1-10 clipping warnings, P1-12 color sample bars) belong on this same stage. Confidence: 0.6

Corollary: delete a dead menu `QAction` whose connect is missing rather than leaving a no-op toggle that looks functional — a single canonical UI surface (the Color Science panel) should be declared as the 正本. - Editor-facing metadata must live in the engine that owns the truth, not be hand-maintained in the UI.
