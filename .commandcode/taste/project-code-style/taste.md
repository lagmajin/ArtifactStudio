# project-code-style
- Do not introduce new QtCSS or `QObject::setStyleSheet(...)` calls in new code; use QPalette, owner-draw, QProxyStyle, or existing theme tokens instead. Confidence: 0.80
- When the stylesheet ban forces owner-draw, take colors from the existing theme API rather than literals: `ArtifactCore::currentDCCTheme()` returning the `DCCTheme` struct (backgroundColor / secondaryBackgroundColor / buttonColor / trackBackgroundColor / borderColor / textColor / textMutedColor / accentColor …), obtained in a widget module via `import Widgets.Utils.CSS;`, then applied through `QPalette` or paint-event overrides following the pattern already used by sibling `Artifact/` widgets. Confirmed acceptable by checking the project rules when planning the expression-editor find bar and line-number gutter (2026-09-26). Confidence: 0.5
- Do not introduce new public `QImage` usage except at IO/compat boundaries; prefer GPU/buffer types. Confidence: 0.80
- Avoid adding new `QObject` signal/slot connections (especially global/centralized event wiring) in new code; reuse existing event paths/services. New public signals/slots need design review. Confidence: 0.80
- Prefers simple callback-based inter-thread communication over Qt signal/slot/emit patterns for worker→main thread dispatch — a single callback dispatched via `QMetaObject::invokeMethod` with `Qt::QueuedConnection`, rather than emit + multi-layer lambda listeners. The user explicitly stated they don't want to use Qt events anymore (「Qtのイベント使いたくない」). This goes beyond "avoid new connections" — the user considers Qt's signal/slot mechanism itself undesirable for the project's architecture. Applied 2026-08-22 in EditorEngine.startExport: worker `std::thread` reports progress via a `std::function` callback bridged with `QMetaObject::invokeMethod(..., Qt::QueuedConnection)`, and completion reuses the pre-existing (never-before-emitted) exportStarted/exportProgress/exportFinished signals instead of declaring new ones. AudioPreviewMixer (2026-08-22) follows the identical shape: level/playback notifications as `std::function` bridged via `QMetaObject::invokeMethod(..., Qt::QueuedConnection)`, plan explicitly 「signal 新規追加なし」. Confidence: 0.90
- When migrating commands onto Core's SerializableCommand base, keep serialization symmetric and self-contained: each command implements `commandType()` as a namespaced constant (e.g. `"nle.moveClip"`), `serialize()` writing only its own members to QJsonObject, and `deserialize()` restoring them + re-setting the QUndoCommand text; reuse existing project-save JSON helpers via forward declarations when they live in the same TU, and verify their namespace/linkage before forward-declaring. Where redo is not idempotent by construction (InsertEdit/OverwriteEdit/LiftEdit create IDs or remove clips), capture the first-redo result in members so repeated redo stays safe under QUndoStack semantics; commands needing pre-computed values expose an explicit compute step (e.g. `computeNewEdges()`) called once before push. Confidence: 0.60
- Do not leave per-frame `qDebug()` logging in playback/render hot paths (e.g. `goToFrame` / timer-tick handlers); when an audit surfaces such logging, treat its removal as an easy inline fix. Confidence: 0.6
- When a rendering backend lacks a native mode (e.g. QPainter has no Subtract blend), do not substitute a visually different approximation (Subtract→Difference); fall back to a neutral mode (SourceOver) with a comment explaining why, keeping the exact implementation on the paths that support it. Confidence: 0.6
- Reader-writer lock (QReadWriteLock) for read-heavy shared state: take QReadLocker on the hot read path and QWriteLocker on the rare write path, so concurrent readers don't block each other (e.g. LocalizationManager.translate() reads under QReadLocker while loadDirectory/reload write under QWriteLocker). Confidence: 0.75
- Re-entrant lock avoidance: an internal/helper method that is only ever called from an outer method already holding the lock must NOT acquire its own lock (would deadlock on re-entry); the caller holds the lock and the callee asserts this assumption in a comment. Confidence: 0.75
- After editing .cppm/.ixx files, verify brace (`{`/`}`) and parenthesis (`(`/`)`) balance by counting both deltas (each must be 0) before running audits or builds. Do this on a view with string-literal contents stripped first — naive counting produces false positives when string literals contain delimiter characters (e.g. the `1)`/`2)`/`3)` numbering inside a translated message reported a phantom `paren -3` in `ArtifactTestMenu.cppm`, 2026-09-18). Keep a string-aware checker (regex-replacing `"..."` with `""` before counting) as the canonical balance tool. Confidence: 0.70
- Evolve widely-used APIs backward-compatibly: extend signatures with optional trailing parameters with defaults (e.g. `std::optional<int> layerIndex = std::nullopt` on `AbstractProperty::evaluateValue`) so existing call sites compile untouched, rather than changing signatures or editing callers. Expose compatibility names as registered aliases to existing implementations (`seedRandom` → `randomSeeded`) instead of duplicating code; prefer pure additions (new registered builtins, no parser/evaluator-core changes) when a minimal-impact pass is requested. Confidence: 0.70
- New shortcut IDs ship with **no default key binding** (unassigned / empty `QKeySequence`), leaving assignment to the user — the user rejected the assistant-recommended default (`Ctrl+Alt+T`) in favor of 未割当て. Registering one requires the full chain (`.ixx` enum entry before `Count` + `Count` increment, `shortcutDisplayName`, the display-name table, `allShortcutIds()`), plus an explicit context mapping in the settings dialog's `shortcutContext()`, whose range-based fallback otherwise files new IDs under `Workspace.Timeline`; `ShortcutBindings` stays the single source of truth (no hardcoded keys in the widget). Not an absolute rule: a later, approved plan shipped `ShortcutId::ViewToggleMagnifier` with the default `Alt+Z` (2026-09-21) after verifying the key was unclaimed — treat 未割当て as the safe default when the candidate key is uncertain, and a conflict-free default as acceptable when the approved plan names it. A batch of *conventional* editor keys is the case where defaults are appropriate: for the expression editor the 11 new IDs shipped with `Tab` / `Ctrl+F` / `Ctrl+H` / `F3` / `Shift+F3` / `Esc` / `Ctrl+=` / `Ctrl+-` / `Ctrl+0` / `Alt+L` / `Alt+Z`, each justified in a code comment by what it shadows. Cross-context key reuse is legal (`Ctrl+=`/`Ctrl+-`/`Ctrl+0` are also Timeline zoom) because bindings only conflict *within* one context and the editor consumes them on its own focused control; a key like `Esc` is acceptable when it is consumed only while that surface's own UI (the find bar) is open. When adding a batch, append the new IDs after the existing ones and bump `Count` so persisted ordinals stay stable, and keep the `allShortcutIds()` append order identical to the enum order because the settings table looks rows up by ordinal. Confidence: 0.6
- A shortcut registered in `ShortcutBindings` is resolved only by the surface that owns the behavior (e.g. the composition viewport resolves `ShortcutId::ViewToggleMagnifier` in its `keyPressEvent` via `ShortcutBindings::matches(event, id)`), and the same key must NOT also be attached to the corresponding menu `QAction` via `setShortcut()` — doing both lets Qt's shortcut machinery consume the key and creates double ownership. Menu entries may display/look up the ID but do not bind the key. Applied 2026-09-21 while adding the accessibility magnifier (the plan's initial `setShortcut` on the View-menu action was removed before delivery). Confidence: 0.5
- After editing files in this repo, verify you have not silently flipped LF→CRLF. The reliable procedure is: count CR-LF byte pairs in the working-tree file, compare against the committed blob (`git show HEAD:<path>`), and normalize only the files your edit actually broke. PowerShell: `[IO.File]::ReadAllText($p)` → `-replace "\`r\`n","\`n"` → `[IO.File]::WriteAllText($p, $t, (New-Object Text.UTF8Encoding($false)))` — the explicit UTF8Encoding($false) avoids injecting a BOM. Two traps: normalizing a file that was ALREADY CRLF in HEAD produces an enormous spurious diff, and a file that was cleanly reverted can still show as modified from a stale stat-cache entry, so confirm with `git diff --stat HEAD -- <path>` before concluding a revert failed. Re-check `git diff --stat` after normalizing to confirm the change stayed minimal. Applied 2026-09-26 across five files (ViewerHelperShaders.ixx, two .ixx files, en.json, ja.json) after edits silently rewrote the whole file with CRLF. Confidence: 0.7
- Before ending a turn, read the full `git diff` hunk by hunk and revert anything that is not part of the intended change: whitespace-only edits on adjacent lines, a blank line swallowed by an anchor-based replace, dead parameters (`Q_UNUSED(format)`), and a local that shadows a member. Anchor-based `edit_file` replacements frequently trim or duplicate the neighbouring line, so a per-file `git diff -- <path>` review is the reliable catch. If an implementation approach is abandoned mid-task, revert the file completely and verify the diff is empty rather than leaving partial scaffolding behind. Applied 2026-09-26 while implementing the viewport exposure feature: three such unintended edits were caught and reverted in `ArtifactIRenderer.cppm`, `ArtifactViewMenu.cppm`, and `ArtifactCompositionRenderController.cppm`, and an abandoned `ApplicationSettingDialog` UI was confirmed to have zero diff. Confidence: 0.65
- Before committing, check the *index* line endings rather than the working tree: `git ls-files --cached --eol <paths>` — `i/lf` means the blob that will be committed is LF regardless of what the checkout shows, so a `w/crlf` / `w/mixed` column entry is a benign checkout-state artifact under a `.gitattributes` carrying `eol=lf` (with `core.autocrlf=false`) and needs no re-normalization. Cross-check with `git diff --numstat -- <paths>`: a small `24 23` proves the CRLF checkout state did not turn the commit into a whole-file rewrite (git compares the LF index against the normalized worktree), whereas insert/delete counts in the thousands mean a real EOL problem. Applied 2026-09-26 while preparing the color-effects commits. Confidence: 0.6
- A comment that names an API (a method called in the prose) is a factual claim and must be checked against the real API surface — during the follow-up verification pass, not only at write time. Found 2026-09-26: a comment written while fixing `ColorGrader` said levels were injected 「`process()` から `setLevels()` で」, but no `setLevels()` method exists — the real code is the assignment `wheelsProcessor_.levels() = levels_` — so the comment described a mechanism that was never there and misled the next reader about the public contract. Corollary: when a later pass verifies a prior change, re-read the comments that same pass touched, not just the code, and prefer describing the actual expression (`wheelsProcessor_.levels() に levels_ を注入`) over naming an abstract setter. Confidence: 0.6
- Long Japanese prose written into files (Insight.md sections, milestone/analysis table rows, doc detail blocks) intermittently comes out with corrupted character runs spliced in — all seen within a single pass on 2026-09-26: 「Bavaria」 inside a Japanese sentence, 「常時」 → 「时常」, 「スライダー」 → 「スライ旅ー」, 「オーストリア」 → 「Austria」, 「1 点サンプル」 → 「1 点Samples」, and a fix that produced 「複数时常時」 instead of 「複数点・常時」. The final chat summary carries the same corruption (「二重に作 COURSE 촉발하는_merge」). After writing any substantial Japanese block, grep the touched files with a marker list (`Bavaria|时常|Samples|Austria|旅|cardinality|Filtered`) and re-read the resulting hunks — then confirm each hit is a legitimate pre-existing identifier rather than assuming it is fine. Recurred 2026-09-26 on a fresh prestudy doc (「而Nt  Providence」, 「having」, 「词典」, 「已经」, 「rester」) and again inside a new Insight.md section. Operational rule: an `edit_file` fix aimed at a corrupted span can fail to match because the on-disk bytes differ from the string being searched, and the corruption is often *invisible* in the read-back — when two successive targeted edits fail to clean a span, stop patching and rewrite the whole file with `write_file`, then re-grep for markers and re-read the file end to end before continuing. Escalation ladder when *every* level fails (2026-09-26, same prestudy doc, five rounds): (1) targeted `edit_file` on the span — failed twice, the second attempt reintroduced a different wrong reading; (2) PowerShell + `python -c` rewriting `lines[N]` by index using `\uXXXX` escapes — produced a *different* wrong kanji each try (差し掲す → 差し挿す → still wrong), because the escapes themselves land wrong; (3) what finally worked — `write_file` the clean single line into a scratch file (`temp/_line.txt`), run a short Python read-modify-write that reads that file and assigns `lines[N]`, then `del` the scratch file. Two lessons: a replacement can *compound* the corruption instead of converging on a fix, so after two failed attempts stop hand-tuning the string and route the clean text through a file; and never trust the tool's success return — the remaining error was only caught because the patch script `print`ed the neighbouring lines back, so always echo the patched region before declaring a file clean. Fresh instances 2026-09-26 (a long Insight.md section plus the chat summary, none flagged by the user): 「不整合」→「不透件」, 「リスクが高い」→「リスク-farm が高い」, and 「Find バー」 → 「Definitions バー」 (an English word substituted for the Japanese term). Because nothing in the turn signals the slip, the post-write marker grep is the only reliable detector — extend the marker list with whatever foreign token appeared. Fresh cluster 2026-09-26 across a 15-commit session, and usefully localized: all of it landed in the **Japanese chat prose**, while all 15 English commit bodies came out clean — so file-written English is not at risk, Japanese is, in either target. Instances: 「コード Biržmi je のコミット・push が完了」, 「泾 dih 清楚了」, 「内容明确了。ArtifactCore の残作業naturalな4単位」, 「ゼロを，首次に E を単独で見ます」, 「現時点ではすべて push 済みで整合pharmacistsanges」 — Czech, Russian-transliterated, Chinese and English morphemes spliced mid-sentence with zero cue. Treat the closing summary as a write target needing the same marker discipline, and re-derive an affected sentence rather than patching it. Confidence: 0.8

- A `ShortcutId` that ships with a default key binding MUST have a consumer in the owning surface's `keyPressEvent` / `eventFilter` in the same pass. An ID with a default but no handler is a user-visible defect, not dead code: the settings dialog renders it as 「Ctrl+F 検索」 while the key does nothing. Verify by grepping every new ID name and confirming one `bindings.matches(keyEvent, …)` branch per ID, and that every control the branch touches is actually constructed and has its event filter installed. Applied 2026-09-26 (expression editor): 4 of 11 new IDs (Ctrl+F / Ctrl+H / F3 / Shift+F3) were registered with conventional defaults but never wired, and a full Find/Replace bar had to be built afterwards to close the gap. Confidence: 0.6
- Self-review of freshly written code should sweep four categories beyond compile blockers, and fix them in the same pass: (1) unused declarations left behind — an anonymous-namespace constant duplicating one owned elsewhere, an `import` no longer referenced, a setter with zero callers; (2) redundant one-line wrappers that add nothing around an existing call (`bool documentFind(...) { return edit->find(...); }`, a getter that returns a literal color); (3) one effect implemented along two paths — the current-line band was painted in `paintEvent` *and* as a `FullWidthSelection` ExtraSelection, double-applying the alpha; keep one drawing path per effect and say in a comment why the surviving one is correct; (4) handlers orphaned by a later change (an Escape branch for a strip that the new find bar's own Escape now supersedes). Applied 2026-09-26. Confidence: 0.6
- Prefer the implementation whose termination is structurally guaranteed over the iterative one when both express the same intent, and record the cost. 「Replace All」 uses `toPlainText().replace(needle, replacement)` + `setPlainText()` instead of walking a `QTextCursor` through `QTextDocument::find`, which spins forever once the replacement string contains the needle; the price paid (undo history, caret and selection are discarded) is stated in a comment so the choice stays a documented trade-off rather than an accident. Confidence: 0.5
