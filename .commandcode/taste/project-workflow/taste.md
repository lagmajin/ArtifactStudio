- For stash triage (e.g. when the user asks 「stashで有用なものあればマージいける？」), the verified workflow is: (1) `git stash list` per repo, then `git stash show stash@{n} --stat` for each — accept that PowerShell `for` loops and `stash@{n}` quoting are fragile, switch to single `git stash show 'stash@{n}' -p | Out-File -Encoding utf8 ...; Get-Content ...` calls when needed; (2) confirm before applying by diffing each stash against HEAD/affected files to check whether the change is already merged (`git log --all --oneline -- <path>`, `git rev-parse HEAD:<submodule>` for gitlinks); (3) for stashes whose only diff is CRLF→LF normalization, empty content, or already-merged submodule gitlinks → `git stash drop` is safe; (4) for stashes that touch files already modified on the working branch or other recently-applied stashes → `git stash apply` may auto-merge cleanly or warn about overwrite; if conflict arises, `git reset --hard HEAD` to abort and **keep the stash** for manual cherry-pick later; (5) Insight.md-conflict stashes (multiple wip snapshots all touching the same Insight.md / milestone docs) are best deferred as a separate manual task rather than force-merged; (6) when a stash mixes valuable parts with already-merged parts (e.g. taste.md updates + submodule gitlinks), filter the diff by path with PowerShell `Select-String -Pattern '^diff --git' | ForEach-Object` and `git apply --check` the filtered patch before committing. Reconfirmed 2026-08-31 during the codex/2026-08-31-dev sync and stash triage across parent/Artifact/ArtifactCore/ArtifactWidgets. Confidence: 0.70
