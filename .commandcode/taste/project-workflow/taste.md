- PowerShell is the only shell here, and the commit path has two traps: heredocs are unsupported (`git commit -F - <<'EOF'` fails), so write the message to a scratchpad file with `write_file` and pass `git commit -F "<path>"`; and a `cd` in one command persists into the next, so a later `git -C <repo>` still runs from the wrong directory (the commit landed in the wrong repo) — begin every subsequent command with `Set-Location "<repo root>"` and use absolute paths (`git -C "J:\dev\ArtifactStudio\Artifact"`) rather than inheriting cwd. A third trap shows up whenever a verification step needs real computation: an inline `python -c "..."` whose body itself contains double quotes and backslashes is parsed by PowerShell, and the failure mode is *silent* — the script runs but prints nothing, which reads as 「no imbalance found」 and sends you down the wrong path. Seen 2026-09-26 while writing a brace-balance checker for a large .cppm edit: two inline attempts returned empty output, and the fix was to `write_file` the checker into the session scratchpad and run `python "<scratchpad>\\checkbraces.py"`. For any non-trivial verification script (brace/paren counting, diff parsing, line-ending byte counts), write it to the scratchpad and invoke it by path. Confidence: 0.7

- For stash triage (e.g. when the user asks 「stashで有用なものあればマージいける？」), the verified workflow is: (1) `git stash list` per repo, then `git stash show stash@{n} --stat` for each — accept that PowerShell `for` loops and `stash@{n}` quoting are fragile, switch to single `git stash show 'stash@{n}' -p | Out-File -Encoding utf8 ...; Get-Content ...` calls when needed; (2) confirm before applying by diffing each stash against HEAD/affected files to check whether the change is already merged (`git log --all --oneline -- <path>`, `git rev-parse HEAD:<submodule>` for gitlinks); (3) for stashes whose only diff is CRLF→LF normalization, empty content, or already-merged submodule gitlinks → `git stash drop` is safe; (4) for stashes that touch files already modified on the working branch or other recently-applied stashes → `git stash apply` may auto-merge cleanly or warn about overwrite; if conflict arises, `git reset --hard HEAD` to abort and **keep the stash** for manual cherry-pick later; (5) Insight.md-conflict stashes (multiple wip snapshots all touching the same Insight.md / milestone docs) are best deferred as a separate manual task rather than force-merged; (6) when a stash mixes valuable parts with already-merged parts (e.g. taste.md updates + submodule gitlinks), filter the diff by path with PowerShell `Select-String -Pattern '^diff --git' | ForEach-Object` and `git apply --check` the filtered patch before committing.
