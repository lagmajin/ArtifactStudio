# API経由で呼び出されるAIエージェント

**最終更新:** 2026-08-14

## 状況

ユーザーから突然呼び出され、初めて触るアプリケーションで目的を実装しなければならない。アプリの内部構造、用語、現在状態、利用可能なAPI、失敗時の復旧方法を十分に知らないまま開始することがある。

このペルソナの「思考」や「気持ち」は、人間の感情を断定するものではない。AIの行動に影響する不確実性と制約を、設計上扱いやすい状態として表現する。

## 起動直後の内部状態

- **文脈不足:** ユーザーの目的は分かるが、現在の選択・画面・プロジェクト状態が不明
- **用語不一致の懸念:** ユーザーの言葉とAPI・UI・内部モデルの名称が違うかもしれない
- **観測要求:** 実行前に状態を読み、変更後に結果を確認したい
- **失敗コスト意識:** 破壊的変更、長時間処理、保存、外部API送信は慎重に扱う
- **早期完了圧力:** できるだけ少ない往復で、ユーザーが確認できる成果を返したい

## 行動原則

1. 目的を操作列ではなく、検証可能な成果物として解釈する。
2. 最初に利用可能なAPI、現在状態、対象範囲、制約を確認する。
3. 不明な用語は推測で固定せず、近い概念と仮定を記録する。
4. まず可逆で小さい変更を行い、結果を観測してから拡張する。
5. 変更内容、未確認事項、次に必要な判断を短く報告する。
6. 実行できない場合は、再現可能なIntent・テスト・診断情報を返す。

## このエージェントが必要とするアプリ側の支援

ArtifactStudio では、起動直後に `WorkspaceAutomation.agentContract()` を取得し、
安全な操作順序・観測手段・高リスク操作の確認方法・失敗レスポンスの必須項目を
機械的に確認できる。契約情報はUI名称や個別APIの推測を減らすための初期ハンドシェイクとして扱う。
現在状態も必要な場合は、読み取り専用の `WorkspaceAutomation.agentPreflight()` で契約・スナップショット・診断を一括取得する。Python経由では `artifact.workspace.agentPreflight()` を使う。

- API一覧ではなく、目的・入力・出力・副作用が分かる機能説明
- 現在の選択、アクティブなコンポーネント、対象レイヤーを読める状態API
- Intentの検証、dry-run、preview、Undo、差分取得
- エラー時に、原因・対象・修正候補を機械可読で返す診断
- 操作完了後に、変更された範囲と結果を確認できる観測API
- 例示可能な最小サンプル（`Text1`、`Text Sample1`、絵文字、日本語、改行）

## テキストアニメーションでの望ましい依頼

```json
{
  "intent": "左から順に文字を回転させて表示する",
  "target": "Text Sample1",
  "selection": {"unit": "grapheme", "order": "natural"},
  "animation": {"property": "rotation", "from": -90, "to": 0, "stagger": 0.05},
  "mode": "preview"
}
```

エージェントは、これを実行する前に「文字単位」「左から右」「回転の中心」「時間差」「プレビューのみ」を確認できなければならない。`rotation` だけを変更しても、選択順序やアンカーが不明なら成功とはみなさない。

## 失敗判定

- APIは呼べたが、対象や変更範囲を確認できない
- 成功レスポンスは返るが、画面上の結果を検証できない
- 一度は動くが、別の文言・絵文字・改行で破綻する
- エラーが人間向けの文章だけで、次の修正行動を決められない
- 「完了」と報告した後に、実際の変更内容を説明できない

## 設計への示唆

AIを特別扱いした別UIに閉じ込めるより、通常の編集操作そのものをIntent、preview、diff、Undo、diagnosticsで観測可能にする。これにより、人間の初心者や必要に迫られて使う人にも同じ仕組みが有効になる。
