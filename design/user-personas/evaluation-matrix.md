# ペルソナ共通評価マトリクス

**最終更新:** 2026-08-13

機能案やテキストアニメーションを、各ペルソナについて次の観点で評価する。評価は「通る／要改善／失敗」とし、可能なら実際のサンプル文字列で記録する。

| 観点 | 確認内容 |
|---|---|
| 到達時間 | 目的の結果までに不要な反復操作がないか |
| 発見性 | 次に何を操作すべきか分かるか |
| 予測性 | 選択範囲、時間差、ピボット、値の影響を予測できるか |
| 整合性 | 文字・単語・行・絵文字・改行で同じ概念が保たれるか |
| 再編集性 | 後から範囲や順序を変更しても構造を理解できるか |
| 復帰性 | Undo、初期化、途中保存で失敗から戻れるか |
| 品質 | 端の文字、合字、絵文字、短文でも破綻しないか |
| 入力負荷 | マウス精度、クリック数、連続操作、疲労を抑えられるか |
| AI親和性 | 意図を自然言語または構造化データで再現できるか |

## 標準サンプル

- `Text1`
- `Text Sample1`
- `こんにちは世界`
- `Á 😀 🧑‍💻`
- 2行の短文

## 最低限の監査質問

1. 「左から順に回転」のような意図を、数値の意味を知らずに指定できるか。
2. 文字を絵文字や別言語に差し替えても選択単位が壊れないか。
3. 同じ結果をプリセット、詳細UI、AI入力の三経路で再現できるか。
4. 途中で操作を止めたり入力方法を変えたりしても状態を失わないか。

## APIエージェント追加監査

API経由で初めて呼び出されたエージェントについては、次も確認する。

1. 実行前に現在状態・対象範囲・副作用を取得できるか。
2. 自然言語の意図を、検証可能なIntentへ変換できるか。
3. `preview`、dry-run、差分、Undoのいずれかで安全に試せるか。
4. 成功時に、実際に変化した対象と値を機械可読で確認できるか。
5. 失敗時に、原因だけでなく次に試せる修正候補が返るか。
