# パン・ズーム診断ログ

**最終更新:** 2026-09-05

## 使用方法

変更を含むアプリを、起動環境変数 `ARTIFACT_VIEWPORT_PERF=1` で起動する。
未設定または0では記録しない。Visual Studioから起動する場合もデバッグ対象の環境変数へ指定する。
ビルド・実機検証は未実施。

平面1枚の同じコンポジション・ウィンドウサイズで、未選択のパン、未選択のズーム、選択したパン、選択したズームを別々に行う。
各操作後に入力を止め、既存の操作終了判定を待つ。保存成功時に `[ViewportPerf] Saved` と絶対パスをログへ1回出す。
保存先はQtのAppLocalDataLocation配下 `Diagnostics/ViewportPerf/interaction-<UUID>.csv`。

## 記録内容と制限

- メインの描画経路を通った操作中フレームのCPU wall time、既存pass時間、draw回数、物理画面サイズ、zoom/pan、実効downsample、操作種別を記録。
- actionは1=pan、2=zoom、3=同一操作区間内で両方。操作イベント単位ではなく描画フレーム単位。
- 固定配列に最大1024行。満杯または前回の保存処理中は待たずにdropし、取得できたCSVのdroppedへ計上。全行dropした操作はファイルなし。
- controllerあたり最大64ファイルの保存試行で停止。再起動で再開する。過去のファイルは自動削除しない。
- 終了時に一括コピーして既存background poolへ渡す。workerはcontrollerやrendererを参照しない。操作中の記録処理には文字列生成、コンソール出力、ファイルI/Oを追加しない。
- 保存中に次の操作を始めた場合、以前の操作のバックグラウンドI/Oは継続する。低負荷比較では保存完了後に次の操作を始める。
- frame_usはCPU側の描画関数内時間で、入力遅延・画面間隔・GPU timestampではない。pass時間は既存のミリ秒計測で、重複を含むため単純加算しない。present_phase_msはreadback等を含む既存区間。
- idleフレーム、早期returnする描画経路、アプリ異常終了までに未保存の操作は記録対象外。終了時に同期書き込みを追加していない。

CSV冒頭に取得行数・drop数・平均/最大frame_us、その後に個別行を出力する。比較時は画面サイズ、downsample、選択状態を揃える。計測負荷と改善効果は実機での確認が必要。

## 入力から描画開始までの追跡

同じUUIDの `.events.csv` を追加保存する。フレームCSVと同じ単調時計の経過マイクロ秒を使う。起点は最初の記録イベント（パンではcontrollerのpanBy入口）で、フレームCSVの先頭が0とは限らない。

kindは1=pan入口、2=履歴処理後、3=rendererのpan反映後、4=操作通知後、5=描画予約後、6=renderOneFrame入口、7=既存frameTimer開始点、8=renderOneFrameImplから戻った時、9=操作終了。

1→2が長ければ履歴処理を含むpan前処理、2→3はpan反映、3→4は操作通知、4→5は描画予約を調べる。5→6は描画呼び出し待ち、6→7は既存フレーム計測より前の処理の候補。6は早期returnした呼び出しも含み、必ず7/8と対になるわけではない。複数の入力が一つの描画へ集約されることもある。

イベントは固定容量4096件で、超過・保存中のdrop数を別に記録。描画フレームが0件でもイベントがあれば保存する。保存上限は64操作（最大128ファイル）。イベントのない空白だけではOS入力キュー、editor側処理、ユーザーの入力停止を区別できない。コントローラーより前の入力時刻は未計測である。
