## ⚠️ あるとめちゃくちゃ嬉しい

誰も要求しないが、一度使うと手放せなくなるもの:

| フォーマット | 効果 |
|---|---|
| `.srt / .ass` | 字幕ファイルをインポートすると自動でテキストレイヤーとキーフレームが生成される |
| `.csv` | 数値のタイムラインを一括インポート |
| `.aseprite` | ドット絵アニメーションをレイヤーとフレームを維持したままインポート |
| `.otf / .ttf` | フォントファイルをドラッグアンドドロップするとテキストレイヤーが作成される |
| `.cube / .3dl` | LUT カラールックアップテーブル |
| `.bvh` | モーションキャプチャ。ufbx が既に FBX/glTF の anim 評価を持つ（`MeshImporter::loadWithUfbx`）ので素通し可能 |

---

## ❌ 殆ど使われないので優先度低

ドキュメントやロードマップに書かれている割に、実際の制作現場では殆ど使われていないフォーマット:

- .fbx - ゲーム開発者は使うがモーショングラフィッカーは殆ど使わない
- .obj - 同上
- .blend - **未実装**（`MeshImporter` に backend が無い）
- .usd - まだ一般的ではない。`.usda` は ASCII パーサ、`.usdc` / `.usdz` は OpenUSD 経由で実装済み

### 残

7.  .svg パスインポート（アニメーション可能なパスとして）
8.  .vmd モーションインポート
9.  .pmx 実装（.pmd と対）
10. .aep プロジェクトインポート

> 重要:
> 最初から完璧な対応をする必要は全く無い。
> 「最初の1フレームだけでも表示される」状態にするだけで、ユーザーは100倍嬉しい。
> 不完全でも良いからまず開けるようにする、それが最も重要。
> 動かないよりは、少しバグがあっても動く方が100倍マシ。

## 🔧 設計上の注意点（2026-10-04 追記）

**ゲートと分類器は別物。** `FileTypeDetector` は「何の種類か」を判定し、`AssetImporter::isSupported` は「その実装があるか」を判定する。両者の拡張子リストが一致しないのは仕様であり、`isSupported` 側だけを実装状況に合わせる。

**OIIO 依存フォーマットは plugin のビルド状態が読めない。** `ico / dds / ktx / avif / heic / jxl / jp2 / pfm` は `isSupported` に載っているが、実際の読み込みは OIIO のビルド時 plugin に依存する。vcpkg port は embedded plugin ビルドの可能性があるため、`out/vcpkg_installed` がない環境では実行時 plugin 列挙で確認が必要。

**DPX の Log transfer は OIIO が `KodakLog` という OCIO colorspace 名で返す。** 同梱 OCIO config にはその定義がないため、`getProcessor` は例外を投げ legacy 経路へ落ちる。`ArtifactImageLayer::effectiveInputTransferFunction` が明示的に `cineon` を名指しすることで `ColorTransferFunction::cineonToLinear()` を確実に発動させる（2026-10-04 修正）。
