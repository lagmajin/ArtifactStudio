## 診断と改善方向

1. 面の明暗差が弱い：外周、パネル、ヘッダー、入力欄、Viewer の明度を役割別に分ける。
2. 文字の強弱が弱い：通常文字を読みやすくし、補足と無効状態を分ける。
3. 密度が不揃い：上部メニューと作業部の文字サイズ・行高の差を縮める。
4. アクセントが散る：青系にまとめ、選択・フォーカス・主操作の表現を整理する。
5. 空表示が間延びする：既存の案内・アイコン・ボタンのまとまりと文字の優先順位を強める。

## 生成条件

元画像を編集対象とし、既存のパネル配置・幅比率・メニュー・操作・空の状態を維持する。明暗、文字階層、操作部の寸法と整列だけを改善する。新機能、パネル、ボタン、キャンバス内の絵・グリッド・ギズモ・HUD は追加しない。既存 File Menu アイコンの形状を変更しない。

生成時の色指定は、外周 `#191B1E`、パネル `#24272B`、ヘッダー `#30343A`、入力欄 `#1C1F23`、Viewer 空背景 `#191C20`、区切り `#41464D`、通常文字 `#E2E6EC`、補足 `#A5ADB8`、無効 `#656D77`、青アクセント `#4C9FFF`。これらは比較検討のための概念値であり、実装用 theme token やコントラスト検証済み値ではない。

画像生成による文字・アイコン・細部の差異は仕様変更の根拠にしない。Composition Viewport の既存承認範囲は [既存 README](../composition-viewport/README.md) を優先する。このモック自体は採用仕様ではなく、実装には別途ユーザーの指示が必要。
