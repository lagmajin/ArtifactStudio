# Editor / Render Rules

この文書は、直近の修正で見えてきた実装ルールをまとめたもの。
迷ったときの判断基準を先に固定して、同じ破綻を繰り返さないために置く。

## Layer / Property

- 初期値系のプロパティは、キーフレーム対象にしない。
- `Initial` 系の値は、レイヤー作成直後の見た目や初期姿勢を決める用途に限定する。
- 初期サイズ、初期角度のような「作成時だけ意味がある値」は `Initial` グループにまとめる。
- レイヤーの「見た目の現在値」と「初期値」は混ぜない。
- `Source Reframe` のような補助機能は、既定では非表示にして、必要なときだけボタンで展開する。

## Composition / Viewport

- 平面レイヤーの描画は、ギズモだけが先に動く状態を許さない。
- ドラッグやギズモ操作で変更した値は、即時にビューへ反映する。
- 再生すると直る、停止中だけずれる、ズームすると戻る、という挙動は表示経路の不整合として扱う。
- コンポジション背景やチェッカーボードは、描画スケールやスクロールに依存して壊れないようにする。
- コンポジション背景色は、アプリ実行中は直前の選択値を既定として使う。

## Transform / Gizmo

- `Scale` や `Rotation` の gizmo 操作は、レイヤー本体と同じ変換経路を通す。
- 初期変換がある場合は、ギズモ操作と初期値の更新責務を分けて考える。
- フレームギズモやスケールハンドルのヒット領域は、操作しやすさを優先して十分に広く取る。
- スケール四角の見た目は、フレームに接地する配置を優先する。

## Cloner / MoGraph / Component

- コンポーネントは、物理、スクリプト、MoGraph のように後から編集できる前提で設計する。
- `MoGraph` を有効にしたら、クローン生成の結果が即座に見える状態を維持する。
- 追加したコンポーネントが他の種類を消してしまう実装にしない。

## Playback / Shortcut

- 再生操作はキーを直書きしない。キーコンフィグ経由で引く。
- コンポジションエディタとタイムラインは、同じ再生トグル経路を共有する。

## Performance / Timing

- Qt のタイマー依存は増やしすぎない。
- フレーム駆動の処理は、アプリ内コアタイマーや既存のフレームループに寄せる。
- 体感 FPS が落ちたら、まずタイマー、再描画、無駄な invalidate を疑う。

## Diagnostics

- 描画デバッグは、`背景 -> レイヤー -> ギズモ` のように pass 単位で追える形にする。
- 各 pass で、描画結果だけでなく、そのとき渡したシェーダ変数も見られるようにする。
- 新しいレンダー方式を導入する場合でも、同じ診断語彙で追えることを優先する。

## Notes

- この文書は実装ルールの整理メモであり、機能仕様書ではない。
- ルールを増やすときは、まず既存の表示経路・入力経路・更新経路のどこで壊れたかを一行で書く。
