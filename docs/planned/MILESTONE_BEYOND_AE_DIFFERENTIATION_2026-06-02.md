# M-BEYOND-AE After Effects にない Artifact だけの差別化機能 (2026-06-02)

これまで73機能提案した。これはその**どれとも重複しない**、AEユーザーが「これAEにも欲しかったんだよ…！」となる機能群。

---

## Z-A: リアルタイムコラボレーション（Google Docs in Motion）

### Z-A1: 複数ユーザー同時編集
Google Docs のように同じプロジェクトを複数人が同時に編集。カーソル位置がリアルタイム表示される。

- [ ] WebSocket / gRPC ベースのリアルタイム同期
- [ ] カーソル位置・選択範囲の他ユーザー表示（名前付き）
- [ ] 楽観的ロック（同じレイヤーを同時編集→コンフリクト時は最終書き込み優先 or 差分マージ）
- [ ] チャットパネル（タイムライン上のフレーム位置をURLで共有）
- [ ] 変更履歴の色分け（誰が何を変えたか）

**AEとの差別化**: AEには**完全にない**。Mac / Windows 環境でもチームで同じ.aepを同時に触れない。
**見積**: 40-60h

### Z-A2: クラウドプロジェクト保存＋自動バージョニング
Git 的なバージョン管理がアプリ内蔵。`.artifact` ファイルを保存するたびに自動でスナップショット。

- [ ] 保存操作をすべて履歴に記録（Undo履歴より長期間保持）
- [ ] バージョン一覧（日時・ユーザー・差分サイズ）
- [ ] 任意のバージョンにワンクリック復元
- [ ] 特定のレイヤーだけ過去バージョンからリストア
- [ ] 差分ビューア（Z-A1のフレーム注釈と統合）

**AEとの差別化**: AEの「バージョン」は手動で別名保存するしかない。Gitのように自動管理されない。
**見積**: 24-36h

## Z-B: ノードベース合成エンジン（Nuke Style）

AEはレイヤーベース。Nuke のノードベース合成を **レイヤーと共存** させる。

### Z-B1: ノードグラフ合成モード
Composition Editor をレイヤーベースとノードベースで切り替え可能に。

- [ ] 既存レイヤーをノードに変換（自動）
- [ ] Mergeノード（Over / Add / Multiply / Screen 等）
- [ ] ノード間の配線UI（ドラッグで接続）
- [ ] ノードツリーの折りたたみ・グループ化
- [ ] 既存エフェクト→ノードとして自動配置

**AEとの差別化**: AEにノードベース合成はない。NukeとAfter Effectsのいいとこ取り。
**見積**: 40-60h（大規模だが既存レイヤーシステムを活かせる）

### Z-B2: ルックデベロップメントターミナル
ノードの出力をリアルタイムでプレビュー。どのノードの出力でも中間結果を確認可能。

- [ ] 任意のノード出力をビューアにピン留め
- [ ] A/Bスプリット比較（2つのノード出力を左右比較）
- [ ] ピクセル値のインスペクション（マウスホバーでRGB値表示）

**見積**: 12-18h

## Z-C: Figma / デザインシステム統合

### Z-C1: Figma プラグイン＆アセット同期
Figma のデザインデータを直接取り込み。テキスト・色・レイアウトを Artifact に同期。

- [ ] Figma API 連携（フレーム/テキスト/ベクター/カラーをインポート）
- [ ] インポートした要素の自動レイヤー化（Figma レイヤー構造を維持）
- [ ] デザイントークン連携：Figma のカラースタイル・テキストスタイルを Artifact のプロパティにマッピング
- [ ] 「Figmaで更新」ボタン→最新デザインに置き換え（アニメーションは保持）

**AEとの差別化**: AEにFigma連携はない。デザイン→モーションの橋渡しが革命的。
**見積**: 20-30h

### Z-C2: コンポーネントベースモーションデザイン
Figma コンポーネントのように、ボタン・ヘッダー・カードなどのモーション部品を「コンポーネント」として定義。1箇所修正→全インスタンスに反映。

- [ ] コンポーネント定義（レイヤーグループ＋アニメーション＋プロパティ公開）
- [ ] インスタンス配置（コンポーネントを複製）
- [ ] マスターコンポーネントの編集→全インスタンスに即時反映
- [ ] オーバーライド（特定インスタンスのプロパティのみ変更）
- [ ] ネスト（コンポーネント内にコンポーネント）

**AEとの差別化**: AEにコンポーネント思想はない。すべて個別レイヤー。
**見積**: 24-36h

### Z-C3: レイアウトグリッド＆オートレイアウト
Figma の Auto Layout をモーションに導入。テキストが増えても自動でサイズ調整＆アニメーション。

- [ ] レイヤーグループに Auto Layout 設定（水平/垂直/ラップ）
- [ ] パディング・ギャップ・整列指定
- [ ] コンテンツ変更時の自動リサイズアニメーション
- [ ] レスポンシブ：コンポジションサイズ変更時にレイアウト維持

**AEとの差別化**: AEにAuto Layoutはない。テキスト変更のたびに手動で位置調整。
**見積**: 16-24h

## Z-D: プロシージャル＆アルゴリズミックデザイン

### Z-D1: プロシージャルシェイプ生成
コード（簡易スクリプト）でシェイプを生成。パラメータ変更で形状が動的に変化。

- [ ] シェイプ生成API：`circle(r)`, `rect(w,h,r)`, `star(n,r1,r2)`, `polygon(n,r)`
- [ ] パラメータをプロパティとして露出（即時反映）
- [ ] ブーリアン演算（和/差/積）
- [ ] 配列で大量生成（1000個の円をグリッド配置など）
- [ ] 乱数シード固定（アニメーションで変化しないランダム shapes）

**AEとの差別化**: AEのシェイプ生成は手動。プロシージャル生成はC4D/Maya の領域。
**見積**: 16-24h

### Z-D2: パラメトリックモーショングラフ
数式ベースでプロパティ値を駆動。グラフを描くようにモーションをデザイン。

- [ ] グラフエディタ内で数式入力（例: `sin(time*2)*100`）+ プレビュー
- [ ] プリセット数式：sine, square, saw, noise, random
- [ ] 数式の組み合わせ（加算/乗算/モジュレーション）
- [ ] 即時プレビュー（数式変更→波形表示→キャンバス上の動きを確認）

**AEとの差別化**: AEのExpressionはテキストで書くしかない。「グラフを描くUI」で数式を視覚化するものはない。
**見積**: 12-18h

### Z-D3: モーションダイアグラム（状態遷移エディタ）
複数のアニメーション状態を定義し、トリガーで遷移。インタラクティブ/ゲーム/プロトタイプ向け。

- [ ] 状態定義（Idle / Hover / Active など）
- [ ] トリガー：クリック/ホバー/時間/キーフレーム到達
- [ ] 状態間のトランジション（イージング＋持続時間）
- [ ] エクスポート：CSS Animation / Lottie に状態込みで書き出し

**AEとの差別化**: AEに状態遷移はない。すべてタイムラインの線形配置。
**見積**: 24-36h

## Z-E: 内部状態・デバッグ・拡張（AEに全くない）

### Z-E1: レイヤーパフォーマンスモニター
各レイヤーのレンダリング負荷をリアルタイム表示。「どのレイヤーが重いか」が一目瞭然。

- [ ] レイヤーリストにレンダリング時間（ms）をカラム追加
- [ ] 色分け：緑(<1ms) / 黄(1-5ms) / 赤(>5ms)
- [ ] エフェクト単位の内訳（「Blur が3ms, Glow が2ms」）
- [ ] フレーム落ち時に自動警告

**AEとの差別化**: AEにパフォーマンスモニターはない（サードパーティプラグインのみ）。
**見積**: 8-12h

### Z-E2: プロジェクト健全性スキャナー
破損リスク・未使用素材・参照切れ・非効率な設定を自動検出。

- [ ] 未使用素材の一覧表示
- [ ] 参照切れファイルの検出
- [ ] 非効率検出（無駄に大きい解像度・不要なエフェクト） 
- [ ] 「最適化」ボタン→一括修正

**AEとの差別化**: AEに健全性チェックはない。
**見積**: 10-16h

### Z-E3: Python / JavaScript 拡張API SDK
スクリプトからプロジェクトの全操作を可能に。ヘッドレスレンダリング対応。

- [ ] プロジェクト作成・編集・保存の完全API
- [ ] レイヤー追加/削除/プロパティ変更
- [ ] エフェクト追加/パラメータ変更
- [ ] ヘッドレスレンダリング（CLIからスクリプト実行）
- [ ] CI/CD連携（GitHub Actions で自動レンダリング）

**AEとの差別化**: AEはExtendScript（独自言語）。Pythonで書ける・CIで回せるのは圧倒的優位。
**見積**: 20-30h

## Z-F: モバイル＆クロスデバイス連携

### Z-F1: モバイルリモートプレビュー
スマホ/タブレットで現在のフレームをリアルタイムプレビュー。実際の画面サイズで確認。

- [ ] ローカルネットワーク経由でストリーミング
- [ ] タップで再生/停止、スワイプでフレーム移動
- [ ] 端末の画面サイズに合わせた表示
- [ ] QRコードで接続

**AEとの差別化**: AEに公式モバイルプレビューはない。
**見積**: 12-18h

### Z-F2: モバイルでタイムライン編集
通勤電車でタイムラインの微調整。クリップのトリムだけでも。

- [ ] クリップ端のトリム
- [ ] キーフレーム位置の微調整
- [ ] マーカー追加
- [ ] 変更のクラウド同期

**見積**: 16-24h

## Z-G: 競合にない映像表現

### Z-G1: ボリューメトリックビデオ
点群データ・奥行きマップを読み込み、3D空間で視点変更可能な映像。

- [ ] `.ply` / `.xyz` 点群読み込み
- [ ] 視点変更に応じた再投影
- [ ] 3D空間内でのテキスト/画像合成

**AEとの差別化**: AEにボリューメトリックはない。Hololens/ARコンテンツ需要。
**見積**: 30-50h

### Z-G2: リアルタイムデータビジュアライゼーション
WebSocket経由でリアルタイムに流れるデータ（株価/センサー/SNS）を直接可視化。

- [ ] WebSocket クライアント
- [ ] データ→グラフ or 数値のリアルタイム更新
- [ ] 遅延補正（バッファリング）

**見積**: 16-24h

### Z-G3: 音声→アニメーション自動生成（Audio Reactor の進化版）
音声のリズム・音量・スペクトラムを解析し、レイヤーアニメーションを自動生成。

- [ ] ビート検出（BPM/テンポ推定）
- [ ] 音量→スケール/不透明度/ブラー量にマッピング（自動）
- [ ] スペクトラム→カラー/位置にマッピング
- [ ] 自動生成されたキーフレームを手動編集可能に

**AEとの差別化**: AEのAudio Amplitudeは手動設定が必要。こちらは「音声入れたら勝手にアニメーション」。
**見積**: 12-18h

## Z-H: Unreal/Unity/Twinmotion Live Link

### Z-H1: Live Link 3Dカメラ
Unreal Engine / Unity から 3Dカメラ情報を受信。ゲームエンジンで動かしたカメラに Artifact の 3D レイヤーが追従。

- [ ] Live Link プロトコル実装（または OSC/MQTT ブリッジ）
- [ ] カメラ位置・回転・FOV のリアルタイム同期
- [ ] フレームバッファリングと補間

**見積**: 20-30h

### Z-H2: マテリアルパラメータのライブリンク
Unreal のマテリアルパラメータを Artifact のプロパティにバインド→Unreal でパラメータ変更→Artifact に即時反映。

**見積**: 12-18h

## Z-I: SNS / ショート動画特化

### Z-I1: 縦型/横型/スクエア 自動アダプト
1つのコンポジションから縦(9:16)・横(16:9)・正方形(1:1)を自動生成。テキスト位置・サイズも自動調整。

- [ ] 各フォーマットのレイアウト設定（Safe Area / Margins）
- [ ] テキスト自動折り返し・フォントサイズ調整
- [ ] 重要領域の指定（自動クロッピング時のキーエリア）
- [ ] 3フォーマットの一括レンダリング

**AEとの差別化**: AEで縦横変換は手動で別プロジェクト作るしかない。
**見積**: 16-24h

### Z-I2: キャプション自動作成
音声認識で自動字幕。フォント・アニメーション・スタイル指定可能。

- [ ] ローカル音声認識（Whisper / Vosk 統合）
- [ ] 自動タイムコード付きSRT生成
- [ ] テキストレイヤーに自動配置＋スタイル適用
- [ ] 手動修正（認識誤りの編集）

**AEとの差別化**: AEに自動字幕生成はない。
**見積**: 16-24h

### Z-I3: テンプレートマーケットプレイス
ユーザーが作ったプロジェクトテンプレートを共有/販売するマーケットプレイス。

- [ ] テンプレートのエクスポート（編集可能パラメータのみ）
- [ ] アップロード/ダウンロード機能
- [ ] 評価・レビューシステム
- [ ] コミュニティ機能

**見積**: 20-30h（サーバーサイド含む）

## Z-J: 内部品質（AEにないアーキテクチャ")

### Z-J1: 完全ノンブロッキングレンダリング
UIが一切フリーズしない。バックグラウンドレンダリングですべてのフレームを生成。

**見積**: 16-24h（マルチスレッド設計次第）

### Z-J2: プロジェクトのgitフレンドリー保存形式
`.artifact` ファイルを ZIP ではなくディレクトリ（人間が読める）で保存。Git 差分が正しく取れる。

- [ ] 各レイヤー・設定が独立したファイルに
- [ ] JSON / YAML / TOML 形式
- [ ] Git で diff 確認可能に

**見積**: 12-18h

### Z-J3: WASM / Web 書き出し
タイムラインアニメーションを WebAssembly 形式で書き出し。ブラウザで60fps再生。

**見積**: 20-30h

## 「これAEに本当にないの？」Top 5

| 機能 | なぜAEにないか | なぜ刺さるか |
|---|---|---|
| **リアルタイム同時編集 (Z-A1)** | .aep がバイナリ排他形式 | Figma/Slack 世代の動画デザイナーには「ない」が信じられない |
| **Figma アセット同期 (Z-C1)** | Adobe と Figma は競合 | デザインツールと動画ツールが統合される未来 |
| **コンポーネント (Z-C2)** | AEにオブジェクト指向思想がない | 1つのマスター編集→全インスタンス反映。制作現場で「これ欲しかった」の声多数 |
| **プロジェクト健全性スキャナー (Z-E2)** | Adobe がやる気がない | 破損プロジェクトで半日無駄にする経験は全モーションデザイナーが持っている |
| **縦横自動アダプト (Z-I1)** | AE時代はTikTokが存在しなかった | モーションデザイナーの新規案件の70%はSNS動画 |
