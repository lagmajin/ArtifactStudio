# M-SMOTION-1: 意味ベースのモーションと相対アニメーション

**最終更新:** 2026-10-13
**ステータス:** Not Started
**対象:** 一般レイヤー向けの意味ベースモーション（登場・退場・強調）と、基準値に追随する相対アニメーション

## 目的

Position / Opacity / Scale を個別にキー設定する代わりに、「登場、力強さ70%、0.5秒」のような意味単位で動きを作成できる基盤を導入する。相対値を評価時に既存の Transform へ適用し、後からレイアウトやベースアニメーションを変更しても効果が追随するようにする。

## 現状と既存資産

- `AbstractProperty` は値、時刻、補間、Bezier、roving、時間リタイム用 anchor などを持つキーフレームを扱う。
- `KeyFrame::Anchor` はレイヤーの In/Out 点に対する**時間位置**を扱う。空間値の相対指定とは異なる。
- `ArtifactAbstractLayer` には共有 Opacity Animation Layer Stack と、プロパティ別 Transform Stack の評価・保存・Undo 基盤がある。一方、専用 Timeline UI とチャンネルの全面網羅は未完了。
- Text Animator は複数プロパティを束ねる評価基盤を持つが、文字選択・文字単位描画に特化している。一般レイヤー用のモーションとして直接流用しない。
- Motion Graphics Template にテンプレートデータとライブラリ導線の実装がある。モーションプリセットをテンプレートとして配布する場合は後続統合とし、初期実装では依存させない。

## 初期仕様案

### 対象とプリセット

初期対象は静止画・シェイプレイヤーの Position / Scale / Opacity とする。プリセットは次の3種から始める。

- **登場:** Opacity を0から基準値へ、Scale を小から基準値へ、Position に開始オフセットを加える。
- **退場:** 登場の逆方向。
- **強調:** Scale を一時的に拡大し、基準値へ戻す。

「力強さ」は移動距離・拡大率などの効果量へ写像し、「長さ」はクリップの時間長とする。初期 UI では方向とイージングを選択可能にする。追従は対象参照・パス・循環依存の仕様が必要なため、このマイルストーンの初期範囲外とする。

### 相対値と評価順

意味モーションは適用時点の絶対座標へ焼き込まず、既存アニメーションの現在時刻評価値に対するオフセット／倍率として保存する。

- Position: ベース位置 + ローカル座標オフセット
- Scale: ベーススケール × 倍率
- Opacity: ベース値に対する明示された乗算または補間

提案する評価順は「既存 Transform / Animation Layer Stack の評価 → 意味モーションの合成 → 既存の親子・描画変換」である。ただし、現行のレンダー経路と親子変換の適用位置を実装前に照合し、全プレビュー／出力経路で同じ順序を通る境界を選ぶ。コンポジション Controller にプリセット固有の低レベル評価分岐を増やさない。

## フェーズ

### Phase 0: 評価経路・データ契約の確定

- 2D Transform の値評価、Animation Layer Stack、親子変換、プレビュー／書き出しの評価経路を追跡する。
- 相対値の型、単位、合成順、クリップ重複時の合成規則、Opacity の合成式を決定する。
- 最小の縦切り対象を Position X/Y と Opacity などに限定し、既存評価を変えない接続点を決める。

### Phase 1: 相対モーションの Core 評価

- 既存 C++20 module とコンテナ方針に沿い、意味モーションの値型と評価 API を設計する。
- 基準 Transform をその時刻に評価し、固定容量／値型の一時データで相対効果を合成する。
- 既存のアニメーションがない場合は、従来の Transform 出力と一致させる。
- この段階ではプリセット UI や汎用キーフレーム形式の変更を行わない。

### Phase 2: クリップデータと永続化

- クリップ ID、種類、開始時刻、長さ、強さ、方向、イージング、対象プロパティ、相対パラメータを保存する。
- JSON のバージョン／既定値を定義し、旧プロジェクトはクリップなしとして読み込む。
- 追加・編集・削除は一つの Undo 操作として復元できるスナップショット境界を設ける。
- 複製・コピー・貼り付け・レイヤー削除で参照や ID が壊れない契約を定める。

### Phase 3: 登場・退場・強調プリセット

- 3種のプリセットパラメータから相対クリップを生成する。
- 同時刻に複数クリップが存在する場合の順序と合成規則を固定する。
- 標準プリセット値はデータ定義として管理し、レンダラー内へ定数分岐を散らさない。
- 必要であれば、非破壊クリップから通常キーフレームへの Bake を提供する。

### Phase 4: UI と Timeline

- Inspector またはレイヤーの既存コンテキスト操作から「登場を追加」などを作成する。
- 長さ・強さ・方向・イージングの編集と、無効化／削除を Undo 対応で提供する。
- Timeline 表示は既存のプロパティキー行を再利用し、クリップ範囲編集 UI の必要性を独立判断する。
- Animation Layer 専用 Timeline UI の未完了計画と責務を重複させない。

### Phase 5: 受入確認と拡張判断

- 保存／再読込、Undo/Redo、複製、シーク、再生、ループ端、クリップ重複を確認する。
- ベース Transform の変更後も相対クリップが追随することを確認する。
- プレビューと書き出しで同一時刻の評価結果が一致することを確認する。
- 追従、テキスト向け意味プリセット、Motion Graphics Template 連携は別途優先度を判断する。

## 受入条件

1. 「登場・力強さ70%・0.5秒」を作成し、Position / Scale / Opacity が一つの Undo 単位で追加・削除できる。
2. ベース位置・スケールを後から変更したときも、相対効果が新しい基準値に追随する。
3. クリップのパラメータ変更は保存・再読込後も維持される。
4. 同一フレームをシーク評価・連続再生評価した結果が一致する。
5. クリップを通常キーへ Bake した場合、Bake 前後の表示が一致し、Undo で復元する。
6. 既存プロジェクトでクリップなしのレイヤーは従来どおり評価される。
7. 時間制約のある評価経路で、フレームごとの重い確保、全キーフレーム複製、GPU リソース再生成を導入しない。

## リスクと未決事項

- Position オフセットのローカル／コンポジション空間。初期値はローカル空間を提案する。
- 「基準値」の定義。各時刻に既存アニメーションを評価した値を使う案を提案する。
- Opacity の合成式。加算は範囲外値を生みやすいため、乗算か基準値への補間を第一候補とする。
- 同種／異種クリップの重複順、負の長さ、ゼロ長、レイヤー端をまたぐクリップの扱い。
- 通常キーフレーム、Animation Layer Stack、意味クリップ間の編集優先順位と Bake 後の所有権。
- プレビューと Render Queue が同じ評価境界を通るか。経路差が見つかった場合は本機能を広げる前に整合を取る。
- 既存キー構造に相対値を直接追加するか、独立したクリップ型にするか。初期案は既存データ互換性と複数プロパティ一括編集を優先し、独立クリップ型とする。
