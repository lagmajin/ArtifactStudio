## 目的

- **Graph API:** `link()` は null と方向だけ確認し、Pin ownerがgraph内か、入力と出力の型が互換か、同一inputへの多重接続かを検証しない。`getConnectedInput()` は最初の接続を返す。`getTopologicalOrder()` は単なる追加順で、legacy `compileHLSL()` は接続順依存である。material loweringはOutputからDFSするため依存順を作るが、未接続dangling inputを既定値へ落とす。
- **JSON:** root versionは1固定、unknown version/nodeはload全体を拒否する。node ID重複・空IDは拒否するが、linkのmissing node/pin/type mismatchはエラーにせずskipしてwarning付き `ok=true`。duplicate input linkも許し、最初のlinkを採用する。deserializeはstaged graphを使うため失敗時にgraph本体は維持される。`toJson()` はnodes/linksの格納順で出力するため、同じ論理graphの挿入順違いはcanonical同値にならない。未知nodeの保持・再保存はできない。
- **Envelope contract gap:** `fromJson()` は`version`を検査するが`kind`は参照せず、`nodes`/`links` missing/non-arrayは`toArray()`でempty扱いとなりload成功しうる。違うdocument kindでもnode typeが既知ならgraphとして受理する。bad linkが混在してもlinkをskipし、全graphをcommitした後 `ok=true` とwarning stringを返すため、callerがboolだけ見ると部分loadを成功と誤認する。wrong-kind、missing-array、Float→BaseColor fixturesと失敗保持/明示reject contract source casesを追加した（未登録・未実行）。
- **Numeric domain gap:** `matFiniteDouble()`はJSON numberをdoubleへ変換した後に`std::isfinite`だけを確認し、Value/RGB/ColorRampなどの値をbinary32 floatへcastする。有限doubleでもfloat finite rangeを超える場合のreject/clamp/diagnostic policyはなく、`1e100` fixtureとexplicit diagnostic contract sourceを追加した。float infinityの下流HLSL表現・backend反応は未実行。
- **Parameter enum domain:** Math opは0..16、MixRGB blendは0..7、ColorRamp interpは0..2、ImageTexture slotは0..5、MapRange interpは0..3へJSON read時にclampされる。例えばMath op=17は最後の有効演算へ黙って置き換えられ、保存graphの見た目/意味が変わる。out-of-range enum fixtureとreject-or-explicit-normalization diagnostic test sourceを追加した（未登録・未実行）。
- **Lowering:** `compileMaterialGraph()` はMaterial Outputがない場合magenta fallback (`ok=false`)。cycleも検出して同fallbackを返す。複数Outputはnodes配列の最初を選びwarning。Outputから到達しないnode/cycleは無視される。Material Output未接続Surfaceは標準Principled定数のwarning。`matConvert()`はnumeric socket mismatchを次の式へ暗黙lowerする: Vector4→Float `.x`; Float→VectorN scalar複製（Vector4のalphaは1）; Vector2→Vector3 `(xy,0)`; Vector2→Vector4 `(xy,0,1)`; Vector3→Vector2 `.xy`; Vector3→Vector4 `(xyz,1)`; Vector4→Vector2 `.xy`; Vector4→Vector3 `.xyz`。同型はそのまま。JSON loaderは型不一致linkをskipする一方、直接`NodeGraph::link()`は保存するため、同じ論理変換でもentry pathで異なる。Shader型違いは既定Principled bundleへ落ちる。Bump→Displacementは別world-normal override。UIのlegacy `ColorNode`/`AddNode`/`OutputNode`はmaterial loweringで拒否される。

### ImageTexture slot/channel contract (source audit)

`ImageTextureNode` always produces the raw sampled `float4 Color` and `Color.a` as `Alpha`; slot selection changes the bound texture variable, not the output swizzle. The fixed PBR path consumes channels by semantic: BaseColor RGB and A (A contributes to material alpha); Opacity A (multiplied into material alpha); Emission RGB; packed MetallicRoughness B for metallic and G for roughness; Normal RGB as normal vector input plus A as average-length term; Occlusion R. This means using `ImageTexture.Alpha` from an arbitrary slot is mechanically allowed even when the conventional PBR path uses another channel, so IR must model raw sample plus explicit swizzles rather than assume semantic output channels. Current node inventory has no Separate Color/XYZ node; implicit Vector4→Float conversion selects `.x`, Vector4→Vector3 selects `.xyz`, and a channel-selecting op is therefore needed to author conventional packed roughness G or metallic B response from a sampled texture. A planned red fixture `planned/separate_color_packed_mr.json` encodes B→Metallic and G→Roughness through a future `SeparateColor` node; current version-1 loader rejects unknown node types, so this remains a product-gap specification only.

The bound image representation also varies by slot: BaseColor is created as sRGB texture; other linear material maps use linear loaders, and Emission has a specialized loader which inspects source color metadata. The graph exposes a packed MetallicRoughness slot, while the standard PBR path also supports independent metallic-only and roughness-only maps which have no corresponding graph enum slots. Graph sampling uses the selected slot SRV but bypasses the fixed path's slot-specific UV set/transforms; exact filter/sampler parity and image color-space behavior across all source formats still need runtime evidence. An unassigned or failed slot is generally replaced by a fallback SRV in renderer setters, so shader compilation cannot distinguish a valid asset from neutral fallback merely by seeing a bound resource.

**Core IR resource contract:** a sample op references a material slot key, explicit UV value, raw channel type (`Color4`), and explicit swizzle when used by a consumer. Runtime dependency metadata should separately report requested slot key, resolved asset identity/revision, color interpretation, UV transform/UV set, sampler state, and whether the result is a neutral fallback or a missing resource. Resource identity/revision belongs to runtime binding/cache invalidation; it should not perturb shader-code hash unless it changes generated operations or compile-time specialization.

### Node-owned JSON parameters and unconnected input defaults (source audit)

`Pin`にはname/type/direction/ownerだけがあり、socketごとのdefault valueを保持・JSON保存するfieldはない。`Pin::getDefaultValueString()`も型単位のzero/default literalを返すだけで、material loweringでは多くの入力に個別fallback literalを別途埋め込む。そのため「接続されていない入力」の挙動はgraph documentの値でなくcompiler実装に固定される。Widgetのnode itemはpin名と型色を描画し、parameter dialogはnode kindごとのnode-owned fields（Value/RGB値、Math/Mix設定、ColorRamp stops/interpolation、ImageTexture slot、MapRange設定）だけを編集する。socket rowにはdefault値の編集UIがなく、unconnected socket値をgraph JSONへ保存する経路は確認できなかった。

| Node | Node-owned fields written/read by JSON | Lowering defaults for unconnected inputs (source) |
|---|---|---|
| Value | `value` | output constant defaults to 0.0 |
| RGB | `r,g,b,a` | output constant defaults to (0.5,0.5,0.5,1) |
| Math | `op` clamped to 0..16, `clamp` | A=(0.5,0.5,0.5,0.5); B varies by op (usually 0, multiply/divide/power/modulo use 1); Mix Fac=0.5 |
| MixRGB | `blend` clamped to 0..7, `clampFactor`, `clampResult` | Fac=0.5, Color1=(0.5,0.5,0.5,1), Color2=(1,1,1,1) |
| ColorRamp | `interp` clamped to 0..2, `stops` (load silently capped at 64; JSON order persists, lowering sorts by position) | Fac=0.5; constructor defaults to black→white stops |
| ImageTexture | `slot` clamped to 0..5 | UV=`In.UV`; texture slot is an existing renderer binding |
| MapRange | `interp` clamped to 0..3, `clamp` | Value=1, FromMin=0, FromMax=1, ToMin=0, ToMax=1, Steps=4 |
| LegacyColor | `r,g,b,a` | Legacy lowering rejected |

Notable remaining pin defaults by node: Fresnel `(IOR 1.45, Normal normalize(In.WorldNormal))`; Layer Weight `(Blend 0.5, same Normal)`; Normal Map `(Strength 1, Color (0.5,0.5,1,1))`; Bump `(Strength 1, Distance 1, Height 0.5, same Normal)`; Invert `(Fac 1, Color black with alpha 1)`; Gamma `(Gamma 1, Color gray 0.5 with alpha 1)`; Hue/Saturation/Value `(Hue 0.5, Saturation 1, Value 1, Fac 1, Color gray 0.8 with alpha 1)`; Luminance `(Color black with alpha 1)`; Clamp `(Value 0, Min 0, Max 1)`; Principled `(BaseColor 0.8, Metallic 0, Roughness 0.5, EmissionColor black, EmissionStrength 1, Alpha 1, Normal=normalSample, Occlusion=occlusionSample)`; Mix Shader `(Fac 0.5, each unconnected shader branch maps to default Principled bundle)`; Material Output without Surface uses the renderer's default PBR bundle with warning. These are source literals, not measured Blender-parity defaults.

JSON parameter values outside known ranges are clamped for enum-like fields; non-finite numeric values read through `matFiniteDouble` fall back to constructor values. Unknown extra JSON parameter keys are ignored, and unknown node-owned editable state cannot round-trip. `ImageTexture` references a slot, not an independently serialized image resource. Two R&D fixtures expose ColorRamp boundary loss: empty `stops` is accepted but ignored, restoring constructor defaults; 65 serialized stops are accepted but silently reduced to 64. Distinct stop positions are sorted only during lowering, so generated shader output should not depend on serialized stop order; a source contract now compares those results. A paired red/blue fixture reverses two stops at position 0.5 and proposes authored stop order as semantic Core state with stable `(position, original array index)` ordering. The independent binary32 formula oracle records linear RGBA samples at 0, 0.4999, 0.5, 0.5001, and 1; factor clamps to the sorted stop domain and exact tie selects the first authored stop. This is candidate Core math only; product review and GPU comparisons remain outstanding. The proposed Core domain rejects non-finite and out-of-range positions before lowering, unlike legacy clamp/fallback. Current lowering uses an unstable comparator for equal positions and a minimum `1e-5` span. The unregistered source case checks document order and lowering success without asserting the unspecified legacy tie result. Executable round-trip and generated-HLSL tests remain required before product compatibility claims.

## 合格・昇格基準

1. Graph formatに明示versionがあり、valid graphのserialize→load→serializeがcanonicalに一致する。
2. cycle、dangling/duplicate input、型不一致、未知node/version、resource欠落を明確に診断し、危険な生成shaderを適用せず既存materialへ安全にfallbackする。

### Compile / Apply failure contract (promotion gate)

現状の`setMaterialGraphJson()`系boolは「3D layerを選択できた」「JSONをlayerへ保存した」「Rendererがgraphを受理した」「shader compileが有効だった」を分離しない。source上ではControllerはJSON保存後にtrueを返し、RendererもJSON load成功後は`compileMaterialGraph().ok`を見ずfallback blockを渡しtrue相当の経路を続ける。UIは別途graphをcompileしてmagenta fallbackを表示する。この差を昇格前に状態として分解する。

Observed stages differ precisely: `ArtifactShaderGraphWidget::applyGraph()` serializes the graph/layout, invokes the Controller mutation, then performs a UI-side `compileMaterialGraph()` probe. Controller true means a selected 3D layer was found and its setter was invoked; the layer setter itself can no-op on identical JSON, and controller still publishes/invalidate/marks dirty. The bool does not report document change or shader compilation. `MeshRenderer::setMaterialGraphJson()` returns false for JSON load failure, true for empty/clear, and after successful JSON load it calls `compileMaterialGraph()` but does not branch on `compiled.ok`; it stores the JSON and sends either normal or magenta fallback HLSL through the void `setMaterialGraph()`/PSO recreation path. A repeated identical payload returns based on stored nonempty block rather than a fresh compiler result. `ArtifactIRenderer.cpp` currently ignores the renderer setter's bool return. Whether `createPSO()` actually produced a usable backend pipeline is not conveyed to UI/controller by these inspected return values.

The renderer source audit now records the downstream failure boundary precisely: `createPSO()` releases the active format's opaque PSO before rebuilding; the Mesh pixel `CompileShader` return is not checked before `CreateGraphicsPipelineState`; opaque PSO failure logs and returns before registering the format-local `pipelineSets_` entry. Draw paths skip when their PSO/SRB is unavailable. Therefore the magenta block produced by graph lowering failure is a diagnostic shader only if backend compilation and PSO creation succeed; backend failure can instead leave the material non-drawable. No last-known-good restoration is visible on this path. The machine-readable `applicationOutcomeContract` keeps these source observations separate from proposed typed stage results and names runtime cases for parse, lowering, shader, opaque/transparent PSO, idempotent repeat, recovery, and clear. These cases are planned, not executed.

### Persistence / clipboard / undo contract (promotion gate)

Source audit (`Artifact/src/Layer/Artifact3DModelLayer.cpp`) shows `Artifact3DLayer::toJsonProperties()` stores nonempty graph JSON verbatim as `material.graph`; `fromJsonProperties()` assigns that string without validating it, and renderer compilation is deferred until drawing. A missing key becomes an empty graph string on load. The graph JSON itself carries node/link/node-owned parameters plus editor layout supplied by `ArtifactShaderGraphWidget::exportLayout()`. Clipboard copy uses the same `NodeGraph::toJson(layout)` representation; paste calls `fromJson()` then rebuilds node positions. Thus semantic graph persistence and canvas layout currently share one payload and one schema version. `setMaterialGraphJsonOnSelectedLayer()` returns true after storing the string and invalidating render state; this reports mutation-path success, not schema validity or backend usability.

Apply ordering is material to history: `ArtifactShaderGraphWidget::applyGraph()` serializes and calls `setMaterialGraphJsonOnSelectedLayer()` first, then runs `compileMaterialGraph()` only for its status probe. A failed probe therefore occurs after the layer document has already changed; the UI reports that magenta fallback will apply. The controller path sets the layer property, publishes layer-modified notification, invalidates composites and marks render dirty, but has no explicit `UndoManager`/`UndoCommand` call in this path. This source observation does not prove that no external history hook exists; runtime undo integration remains unverified. Clear follows a separate controller method with similarly no visible explicit command construction.

**R&D acceptance cases:** (1) apply graph A, apply graph B, undo/redo and compare exact semantic graph payload plus effective shader; (2) capture before/after graph including layout and verify the chosen undo contract restores both or intentionally separates layout history; (3) invalid load from project must preserve the serialized bytes for repair even if renderer rejects application; (4) invalid Apply must either be rejected before changing stored layer state or explicitly record the invalid document while preserving last-known-good effective shader; (5) graph clear, layer duplicate, clipboard paste and save/reload preserve node IDs, links, parameters, resources and positions; (6) undo/redo after layer selection changes targets the original layer ID and preserves selection/current frame/dirty/cache behavior as specified; (7) a clipboard payload with unknown node/version or malformed link is rejected without replacing the current editor graph; (8) a legacy payload without layout and a current payload with layout both survive layer save/reload, copy/paste and schema migration without changing semantic graph hash. Evidence must include command label, before/after payload/hash, layer identity, effective shader state and failure/cancel result.

**Current status:** project serialization and clipboard source paths are identified, but executable save/reload, duplicate, undo/redo, and failure-injection evidence is missing. No Shader Graph-specific undo command was found in the inspected controller apply/clear methods. The persistence/history gate is open; do not infer undo support from a changed-layer notification.

### Graph ownership and resource bounds (promotion gate)

`NodeGraph::link()`は現在pin方向だけを確認し、pin ownerがこのgraphのnodeか、socket typeが同じか、single-writer inputかを検査しない。Linkはraw `Pin*`を保持し、compile traversalとserializerはsource/targetのownerをたどる。このため別graph由来のPinが混入すると、所有元graph破棄後にdangling pointerを参照する危険がある。direct APIからforeign pinと型違いpinを拒否するsource testを追加したが、現行実装では失敗する想定で未実行。

`addNode()`/`link()`/`fromJson()`にはnode/link数の明示上限がなく、`compileMaterialGraph()`はoutputから再帰DFSする。graph depth/resource limitがない状態では極端に深いJSONでstack枯渇するリスクが残る。Core昇格前に最大JSON bytes/node count/link count/traversal depthとColorRamp stops limitを決め、過大入力を割当て前にdiagnostic付きで拒否できるか確認する。DFSはstack-safeな反復処理か明確にboundedなrecursionにし、large/deep valid/invalid fixtureでfailureがcrashや無制限allocationにならないことをruntime検証する。数値上限は実測前に捏造しない。

閾値・性能予算は現状値を測定してから明文化し、最終候補比較前に固定する。未達・未計測項目を合格扱いしない。

## Dynamic registry prototype (2026-11-14)

`experiments/ShaderGraphLab` is a source-only vertical slice for data-driven graph authoring. `registry.json` declares versioned Float math/source nodes, a Vector4 constant with four finite binary32 parameters, and two explicit conversion nodes: Float→Vector4 RGB replication with alpha=1 and Vector4→Float X extraction. The prototype validates the full document, checks exact socket types/single writers/required inputs/cycles/finite binary32 values and sanitized symbol collisions, prunes only after validation, deterministically orders the active subgraph, and emits a layout-free semantic SHA-256 plus HLSL body candidate. The semantic projection includes the closed implementation ID as well as operation ID/version, preventing the same unsealed document hash from aliasing distinct registered implementations.

`tests/fixtures/shader-graph-rd/dynamic_add_lowering_candidate.json` captures the generated result for `(0.25 + 0.5) * 2`. The R&D manifest validator regenerates the output and checks layout/order invariance, unreachable-node pruning, and editing a known node's parameter/layout while retaining an unknown-version node's vendor fields plus a link referencing an unknown socket. All are source-only prototype checks; no HLSL compiler, GPU, production UI, serialization migration, or ArtifactCore path is exercised. The prototype pins stable codes, severity, and JSON Pointer paths for eleven representative schema and semantic failure classes. This probe demonstrates JSON-level retention only; it does not demonstrate production editor interaction, actual save/reload, or undo behavior. Additional malformed registry/document cases still need diagnostic fixture coverage before Core admission.

Registry ingress has manifest-covered negative cases for unknown operation fields, duplicate operation/version registrations, and duplicate socket IDs; each is rejected before a palette or compiler can consume an ambiguous definition. The loader now also explicitly rejects boolean/non-integer schema versions and non-string implementation/socket/parameter type tags, preventing unhashable JSON values from escaping as Python `TypeError`. File ingress validates JSON value depth before iterative forbidden-code-field scanning, and parser recursion failures map to a structured depth diagnostic. Editing APIs route serialized node identity lookups through a type-safe helper, so malformed version values resolve as unavailable operations instead of leaking hash errors.
