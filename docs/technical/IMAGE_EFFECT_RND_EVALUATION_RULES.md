# 画像エフェクト R&D 画像評価ルール

**最終更新:** 2026-11-11

## 適用範囲

画像処理・合成・キーイング・ブラーなど、出力画像の品質を目的とする R&D に適用する。新規プロジェクトは開始前にこのルールを満たす評価計画を作る。進行中のプロジェクトにも適用し、不足する評価は未実施として記録し、完了判定までに埋める。調査開始のための準備や baseline 取得は可能だが、評価計画の不足を品質達成の根拠にしない。

## 開始前に決めること

1. **目的と対象:** 改善したい見た目、対象素材・操作・レンダー経路、対象外を明記する。現状が未確認なら未確認と記す。
2. **比較対象:** 現行出力を baseline とし、必要に応じて合成 ground truth、承認された目標画像、外部参照を用意する。それぞれの役割と正解として扱える根拠を記す。実写や他製品の画像を無条件に物理的正解としない。
3. **評価素材:** 典型例と失敗しやすい例を含め、効果に関係する細部、境界、透明度、高輝度、極端な設定を選ぶ。必要なら連続フレームを含める。素材の出所、利用条件、バージョンまたはハッシュを記録する。
4. **画像条件:** 入力、設定、解像度、色空間・転送関数、露出・表示変換、alpha の扱い、フレーム、乱数 seed、出力形式を固定または記録する。比較に使う画像の条件を揃える。
5. **評価と合否:** 下記の共通項目から適用可否を判断し、効果固有の項目を追加する。各項目に評価領域、手順、判定者、合格条件、許容差、重大な欠陥を決める。数値は対象と測定方法に即して設定し、根拠なく共通の閾値を流用しない。baseline 取得後に閾値を定める場合は、その期限と方法を開始前に記し、候補の最終比較より前に確定する。
6. **実行条件:** 対象 GPU・バックエンド、プレビュー／最終出力、必要な処理時間・メモリ予算と測定条件を決める。利用できない環境は未検証として記録する。

## 必須の評価項目

各項目は適用、対象外の理由、または未検証を明記する。対象外は具体的な理由なしに省略しない。

| 項目 | 確認内容 |
|---|---|
| 効果の正しさ | 意図した画像応答、パラメータ変更時の連続性、無効・中立設定時の挙動 |
| 画質と細部 | 全体像と重要領域の等倍・拡大画像で、輪郭、細線、ディテール、ノイズ、halo、banding、色にじみなど対象固有の破綻 |
| 色と alpha | 色空間、HDR／高輝度、透明・半透明、straight／premultiplied の入力と出力契約、背景合成後の縁 |
| 時間安定性 | 動きや設定変更時の flicker、shimmer、ghosting。時間変化が適用されない場合は理由を記録 |
| 経路と解像度 | 対象の preview／最終出力、解像度、GPU・バックエンド間の差と、その許容範囲 |
| 性能 | 対象条件での処理時間・GPU メモリ等を baseline と比較し、画質と予算の両方を判定 |

## 画像統計による評価

各 R&D は評価目的に合う複数の統計を選び、画像全体と、欠陥が現れる領域を分けて測定する。少なくとも画素値分布、参照との差分、効果固有の測定を検討し、適用しないものは理由を記録する。正しい参照がない場合は参照差分を未適用とし、分布や効果の応答だけで正解を証明しない。

| 測定 | 例と用途 | 注意点 |
|---|---|---|
| 画素値分布 | RGB・輝度・alpha の最小／最大、平均、中央値、分位点、ヒストグラム、クリップ率、非有限値数 | 平均だけでは局所的な破綻が隠れる。HDR の値域を 0〜1 に丸めず、クリップの定義を指定する |
| 参照との差分 | チャンネル別の絶対誤差、MAE、RMSE、最大値・高分位点、閾値超過画素率、差分画像 | 同じ画像内容と座標・色・alpha 条件が必要。小さいずれでも大きな差になる |
| 構造と細部 | エッジ幅・強度、細線の保持、局所コントラスト、周波数分布、適切な場合の SSIM／PSNR | 意図的なぼかしや質感変更では、入力との差が大きいこと自体は欠陥ではない |
| 色 | 輝度・色差の分布、チャンネル別の偏り、必要に応じて定義済み色空間での色差 | 評価空間と表示変換を明記する。色差指標の適用範囲を HDR 等へ無条件に拡張しない |
| 透明度・境界 | alpha の分布、前景／背景漏れ、境界帯の誤差、複数の背景色への合成後の差 | 透明画素の RGB と表示結果を区別し、alpha が小さい領域の除算条件を明記する |
| ノイズ・時間 | 平坦領域の分散・空間分布、固定条件のフレーム間差、時間方向の分散や分位点 | 動きや意図的な変化を flicker と混同しない。必要なら対応位置を揃え、方法と限界を記録する |
| 効果固有 | DoF の焦点面・ボケ形状・境界漏れ、keying の matte や spill など | 対象と測定方法を個別に定義し、他の効果の尺度をそのまま合格基準にしない |

領域は全体に加え、前景・背景・境界・平坦部・高輝度部などから対象に応じて選ぶ。領域の座標やマスク、その生成方法、画素数を保存する。平均と併せて分位点・最大値・閾値超過率を確認し、少数の重大な異常が全体集計で埋もれないようにする。

測定結果には、入力／参照の識別情報、領域、測定空間・値域、alpha の扱い、指標の定義・単位、集計方法、ツールとバージョン、許容値、結果を残す。差分画像の表示倍率や正規化も記録し、表示用画像と測定に使用した元データを区別する。圧縮や量子化による差が問題になる場合は、測定用に情報を保持できる形式を使う。

統計は目視レビューと組み合わせ、指標の改善だけで視覚品質の向上を断定しない。測定できない項目は未検証として扱い、代わりの指標を使う場合は証明できる範囲を明記する。

## 比較と判定

- 全体画像と評価領域の crop を残し、同じ表示条件で目視確認する。必要な場合は複数背景への合成も確認する。
- 数値比較は評価目的に合う指標と領域を選び、単位・閾値・集計方法を記録する。PSNR／SSIM や画素差分は補助指標であり、単独で画質全体の合格を証明しない。完全一致は決定的に一致すべき契約に限って要求する。
- 候補と baseline は同じ入力・条件で比較し、品質改善と新たな欠陥、性能・メモリへの影響を併記する。条件が揃わない場合はその制約を明記し、同等比較と主張しない。
- 欠陥ごとに場所、再現条件、影響、重大度、証拠、対応状況を記録する。重大な欠陥や必須項目の未検証は合格扱いにしない。
- 閾値や対象を評価後に変更する場合は、変更理由、変更前後、承認者、影響する結果を残し、必要な比較をやり直す。

## 証跡と完了条件

第三者が再現できるよう、入力・参照・出力への参照、取得手順、設定、環境、実行日、画像全体と crop、測定結果、判定者、既知の制限を保存する。素材をリポジトリに置けない場合も、アクセス方法と識別情報を記録する。数値契約テスト、画像評価、実アプリ経路、性能計測の証明範囲は区別する。

R&D の完了には、必須評価の結果、合否と根拠、未解決事項、採用／不採用判断、および後続実装の受入条件を残す。未達や未検証が残る場合はそのまま明示し、画質達成や製品統合完了と表現しない。R&D の完了自体は製品実装や新機能追加の承認を意味しない。
