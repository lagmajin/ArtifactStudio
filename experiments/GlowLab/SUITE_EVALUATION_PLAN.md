# Glow Effects Suite R&D

**最終更新:** 2026-11-11

## Goal

Research a suite of distinct Glow effects on shared image plates, then promote only accepted looks into ArtifactCore and Artifact. The primary suite is the 12 registered Glow-family effects below. Still Light Leak is a companion optical-effect track with its own three looks; it is researched alongside Glow but does not stand in for the Glow suite. Existing effect names or implementations do not count as quality acceptance.

## Suite map

Organize the suite by what each effect contributes. This allows multiple looks to share a foundation while keeping each specialist's identity and acceptance checks separate.

| Suite group | Effects | Contribution to a look | Main evaluation question |
|---|---|---|---|
| Foundation halo | `glow` | Broad, soft, multi-scale energy around light sources | How much halo can be added before a veil or highlight clipping obscures the plate? |
| Source response | `edge_bloom`, `reactive_glow` | Preserve emissive contours or adapt tint/strength to source luminance and saturation | Does the source stay legible while nearby skin, dark regions, and practicals keep their color? |
| Spectral and refractive detail | `chromatic_glow`, `liquid_glow`, `luminescence_caustics` | Split color edges, ripple glow, or add fine caustic ridges | Is the signature visible at 1:1 without hiding text, changing object edges, or aliasing? |
| Direction and point structure | `directional_glow`, `builtin.volumetric_shine`, `builtin.glint_star_filter` | Stretch light, emit rays from a point, or shape compact highlights | Does each shape read distinctly and follow the intended source/orientation? |
| Film optics and history | `physical_halation`, `builtin.optical_glow`, `residual_glow` | Warm red diffusion, layered optical components, or a time-carried trace | Is color spread and temporal persistence controllable without unwanted casts or trails? |
| Companion optical track | `still_light_leak` | Edge wash, anamorphic streak, or organic leak | Which of its three looks and source placements fit the plate? Keep its acceptance separate from Glow. |

## Primary comparison: standalone family lineup

The main deliverable is a set of distinct, independently selectable Glow-family looks. Compare one specialist at a time from the same source image and identity input, with a role-specific profile, normal-view output, native-scale ROI crops, alpha and local clipping evidence. Shared-foundation pairs are a secondary recipe study: they test complementarity after a family's standalone signature is legible. Do not infer a suite from effect names or one shared Amount value.

## Acceptance checks

For each family, compare the current product baseline and independent candidate on full image plus 1:1 crops. Inspect shape identity, bright-line separation, local contrast, color spill, new clipping, alpha edges, and neutral settings. For temporal families, inspect consecutive frames and fixed ROI drift. Record CPU/GPU/backend and preview/final route separately. Measure elapsed time and temporary/resource behavior before adopting a candidate. There are no common numeric image thresholds yet; set effect-specific bounds after baseline captures and before candidate selection.

## Ordered multi-effect stack experiment (in progress)

**Question:** Which distinct Glow roles still help when they are applied in order on one image, and which roles overlap or consume too much highlight headroom? The experiment is for a suite recipe, not a parameter ranking.

**Materials and baseline:** Use the CC0 1536×1025 aerial night photo as the primary plate with fixed ROIs `central_intersection`, `bright_roads`, `red_practicals`, and `dark_city_blocks`. Use the existing 1536×1024 low-light portrait as a second plate to check skin spill and face detail. Compare the original input, Glow-only foundation, and every intermediate/final stack stage. The photo captures are opaque 8-bit PNGs from the installed CPU reference; the source-derived Python model is not ground truth. Record source, capture, property, executable hashes, effect order, UI language, alpha, dimensions, state sidecars, and stage timings if available.

**Pre-candidate foundation calibration:** Measure Glow-only gain 0.10 / 0.25 / 0.50 / 1.00 against the unmodified photo. Report encoded RGB, linear luma distribution (mean / p95 / maximum), newly clipped channels using the established 254/255 display proxy, and these same values for every fixed ROI. Set the shared foundation before comparing specialist stacks; gain 1.0 has already added 16.1% newly clipped channels in the city-intersection ROI, so do not use it as an assumed safe base.

**Candidate recipe review:** Capture each ordered sequence through the registered CPU effect fixture, keeping input and property values fixed. Save original input, foundation, each intermediate, final output, a full-frame contact sheet, and 1:1 ROI crops. Compare each stage to both its previous stage and the original. Require exact alpha preservation for the opaque photographic plates. Flag a candidate for rejection/tuning when the incremental newly-clipped-channel fraction exceeds 1% full frame or 3% in any key ROI; this is a review gate, not a universal quality law. A recipe is not a visual pass unless all intended roles remain distinguishable at 1:1, critical structures remain legible, broad casts and false rays are absent, and the portrait has no distracting skin/face spill. The user makes the final aesthetic acceptance decision from the contact sheets.

**Scope limitations:** CPU installed-effect output with 8-bit PNG handoff is only an ordered-stack proxy. GPU, final Composition Viewer, HDR, transparent-edge composites, multiple backend parity, temporal behavior, and render-time/allocation budgets remain required before product promotion. Run no build or CMake as part of this experiment.
