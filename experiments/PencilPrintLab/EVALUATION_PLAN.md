## 1. 目的と対象

### 改善したい見た目

静止画／連番画像を、輪郭と濃淡から構成される「鉛筆画／版画風」へ変換する。次の3成分を分離して評価する。

- **line（線）:** 輪郭から連続した線を生成する。細線が途切れず、不要な線が増えないこと。
- **tone（濃淡）:** 明度を段階化または網点化する。階調が飛び、細部が黒く潰れる失敗を防ぐ。
- **texture（紙／ハッチング）:** 鉛筆の粒状感や版画の網点規則性を与える。規則的なタイル目やノイズ化は失敗例。

「鉛筆画らしさ」の物理的正解を主張しない。評価は再現可能な応答と目視の相対比較であり、実作品との一致を合格条件にしない。

### 対象素材・操作・経路

- **素材:** 決定論的 fixture（opaque／alpha 付き）とライセンス確認済みの CC0 静止画。連番画像は時間安定性の評価にのみ使う。
- **操作:** オフライン Python / NumPy / OpenCV の reference model。学習モデルは使わない。パラメータは `line` / `tone` / `texture` と各強度（0 / 中 / 最大）、seed。
- **経路:** オフライン fixture のみ。Artifact の Composition、Render Queue、preview／final、GPU（D3D12 / Vulkan）は対象外・未検証。

### 対象外（未検証として明記）

- 学習型 stylization（ONNX / DirectML）、実画材の物理シミュレーション
- 製品 effect 登録、Inspector プロパティ、既定値、Undo、project 保存／再読込
- 実アプリの画像到達、CPU／GPU parity、backend 差、性能 gate
- 動画デコードを含む本格的な時系列対応（連番 8 フレームの安定性評価のみ）
- HDR（1.0 超）と OCIO 色空間（現段階は SDR / sRGB のみ）

## 3. 評価素材

### 3.1 決定論的 fixture

seed `20261118`、解像度 512×320 と 1536×1024 の2段。生成手順・hash を manifest に保存する。

| fixture | 目的 | 失敗しやすい例 |
|---|---|---|
| 8 色パッチ + 灰色 ramp | 段階化による階調飛び、色の潰れ | 中間調が 2 値化される、ramp に段差 |
| 細線／枝チャート（1〜4px、複数角度） | 線の連続性と細線保持 | 線が途切れる、二重線（halo）、黒く潰れる |
| 高コントラスト境界 + 半透明 alpha 境界 | 線と alpha の相互作用 | 黒／白フリンジ、hidden RGB の漏れ、alpha の段差 |
| 平坦部 + 高輝度スポット | 紙目／ハッチングの分散とクリップ | タイル目、高輝度の丸め |
| 連続フレーム 8 枚（0.5px 平行移動） | 線と網点の時間安定性 | 線が揺れる、網点が流れる、flicker |

### 3.2 実写素材

- GlowLab で provenance を確認済みの CC0 画像を再利用候補とする。出所・ライセンス・SHA-256 を本ラボの manifest に参照情報として記録する。
- 人物の肌・髪や印刷物の CC0 素材は現時点で**未取得**。取得までは実写での品質判定を未検証とする。
- いかなる素材も無条件に正しいとは扱わない。

## 4. 画像条件

| 項目 | 固定／記録する条件 |
|---|---|
| 入力 | linear float（`ImageF32x4_RGBA` 相当）と 8-bit sRGB の2条件を分ける。fixture は linear float で生成し、PNG は sRGB OETF で encode |
| 設定 | `line` / `tone` / `texture` を 0 / 中 / 最大。seed 固定 |
| 解像度 | 512×320 と 1536×1024 |
| 色空間・転送関数 | sRGB 8-bit と linear。表示変換は sRGB OETF 固定 |
| alpha | straight と premultiplied の両方を明示し、入出力契約をテストする |
| フレーム | 0〜7（時間安定性評価のみ） |
| 出力形式 | 目視用 PNG 8-bit と測定用 float32 `.npy` |
| 表示 | 差分画像の倍率・正規化を記録し、表示画像と測定元データを区別する |

**alpha 契約:** 前回の水彩 R&D で得た知見を引き継ぐ。近傍演算（Sobel、網点、ハッチング、blur）は premultiplied RGB と alpha を**同じカーネル**で処理し、最後に一度だけ unpremultiply する。descriptor 差が 0 でも絶対値が健全とは限らないため、可視領域と近透明領域の両方で復元 RGB の最大値を記録する（水彩 RD3 / RD4 の知見）。

## 5. 評価項目と合否

### 5.0 閾値の確定手順（開始前の登録）

RD0 で baseline（無処理＋2 control）の full 画像と固定 ROI crop を取得した直後、**候補の最終比較より前に**、実装者とは別のレビュー者が各項目の許容差を数値で事前登録する。

- 対象: §5.1〜5.6 の合格条件欄と §5.7 の効果固有項目
- 方法: baseline と control の full／crop を同じ表示条件で見て、領域ごとに許容できる変化量を決定
- 記録: 決定日時、根拠、判定者、変更前後をこの文書へ追記
- ルール: 未記入項目は未評価とし、R&D 合格に含めない。評価後の変更は理由・前後・承認者・影響を記録し、必要な比較をやり直す
- 他 R&D の共通閾値を流用しない。PSNR / SSIM の固定値を単独の合格基準にしない

### 5.1 効果の正しさ

- **領域:** 全体、8 色パッチ、灰色 ramp、細線 ROI
- **手順:** (a) `line=tone=texture=0` で入力との差分を測る。(b) 各パラメータを 0→中→最大で線幅・段階数・粒状分散が単調に変化するか。(c) 合成 ground truth の既知領域を再現するか
- **判定者:** 実装者＋別レビュー者
- **合格条件:** 中立設定で 8-bit 差 0、float 差 1e-6 未満。応答が単調。許容差は §5.0 で固定
- **重大な欠陥:** 中立設定で画像が変わる、パラメータ増で応答が反転する

### 5.2 画質と細部

- **領域:** 全体、細線 ROI、平坦部 ROI、高コントラスト境界 ROI
- **手順:** baseline／control／候補の full と 1:1・拡大 crop を blind review。線の連続性、黒潰れ、halo、段差、網点の規則性を記録
- **判定者:** 別レビュー者（候補名を伏せて判定）
- **合格条件:** 細線が残存し、平坦部で黒潰れ／段差がない。許容差は §5.0 で固定
- **重大な欠陥:** 細線の消失、1px 線の黒潰れ、可視 halo、タイル目

### 5.3 色と alpha

- **領域:** 8 色パッチ、半透明 alpha 境界、透明画素、高輝度スポット
- **手順:** straight／premultiplied で un-premultiply 後の RGB を比較。黒／白／中灰の3背景へ合成した縁を比較。クリップ率と非有限値数を測る
- **判定者:** 実装者＋別レビュー者
- **合格条件:** 両 descriptor で復元 RGB 差が 1e-5 未満、かつ近透明領域の復元 RGB 最大値が §5.0 の許容内。3背景でフリンジなし。非有限値 0
- **重大な欠陥:** alpha が小さい領域で RGB が発散する、背景依存の縁色

### 5.4 時間安定性

- **領域:** 固定領域、移動パッチ周辺、線と網点
- **手順:** 0.5px 平行移動 8 フレームで対応位置を揃えてフレーム間差を測る。整数移動では content-locked パターンが共変するか確認
- **判定者:** 実装者
- **合格条件:** 動きに起因する変化を flicker と誤判定しない。許容差は §5.0 で固定
- **重大な欠陥:** 激しい flicker / shimmer、線の揺れ、ghosting

### 5.5 経路と解像度

- **領域:** 512×320 と 1536×1024 の same-content 画像
- **手順:** 同じ seed・設定で2解像度を生成し、線幅・段階数・網点周期の傾向を比較
- **判定者:** 実装者
- **対象外:** 製品 preview／final、D3D12／Vulkan 差（未検証として明記）
- **重大な欠陥:** 低解像度で線が消える、網点がエイリアスする

### 5.6 性能

- **領域:** オフライン reference model の実行時間とメモリ
- **手順:** 2解像度で warm-up 後に複数回計測し、中央値と最大値を記録
- **判定者:** 実装者
- **合格条件:** オフライン探索が現実的な時間で回ること。製品の 1080p / 4K gate は未実施として記録
- **重大な欠陥:** fixture すら回らないほどの消費

### 5.7 効果固有の項目

| 成分 | 測定 | 領域 | 備考 |
|---|---|---|---|
| line（線） | 線の連続性、1px 線の残存率、線幅のばらつき、二重線の有無 | 細線 ROI | 途切れと黒潰れを重大欠陥候補にする |
| tone（濃淡） | 段階数、ramp の flat-step 率、逆転率、黒クリップ率 | gray ramp、8 色パッチ | 2 値化への退化を検出する |
| texture（紙／ハッチング） | 平坦部の分散・空間周波数、網点周期の規則性、タイル目 | 平坦部 ROI | ノイズ化と区別する |

## 6. 画像統計による評価

- **画素値分布:** min / max / mean / median / 分位点 / ヒストグラム / クリップ率 / 非有限値数。HDR の 0〜1 丸めをしない
- **参照との差分:** 合成 ground truth に対する MAE / RMSE / 最大値 / 高分位点 / 閾値超過率 / 差分画像。実画像に正解がないため実画像との差分は参照差分として適用しない
- **構造と細部:** エッジ幅・強度、細線保持、局地コントラスト、周波数分布。SSIM / PSNR は補助指標に留める
- **色:** 輝度・色差分布、チャンネル偏り。評価空間と表示変換を明記
- **透明度・境界:** alpha 分布、前景／背景漏れ、境界帯誤差、3背景合成後の差。透明画素の RGB と表示結果を区別
- **ノイズ・時間:** 平坦部の分散、固定条件のフレーム間差、時間方向分散。意図的な質感と flicker を混同しない
- **効果固有:** §5.7 の line / tone / texture
- **領域:** 全体に加え前景／背景／境界／平坦部／高輝度部／細線部。座標・マスク・生成方法・画素数を保存。平均と分位点・最大値・閾値超過率を併記
- 目視レビューと組み合わせ、指標の改善だけで品質向上を断定しない

## 11. 実行履歴（RD0〜RD10）

各段は別 run として記録し、gate 未設定の段階では合格判定・順位付けを行わない。

| RD | 内容 | 記録 |
|---|---|---|
| RD0 | 決定論的 fixture と baseline | `captures/rd0/` |
| RD1 | 候補 6 種（line / tone / texture の ablations） | `captures/rd1/` |
| RD2 | descriptor 安全（straight / premultiplied の一致） | `captures/rd2/` |
| RD3 | HDR 保持の量子化上限 | `captures/rd3/` |
| RD4 | 多値 Bayer | `captures/rd4/` |
| RD5 | dither 段階の sweep | `captures/rd5/` |
| RD6 | 深い時間解析（整列 MAE、seek 相当 MAE、flicker proxy） | `captures/rd6/` |
| RD7 | content-locked dither（既知の変換量を供給する制御実験） | `captures/rd7/` |
| RD8 | 隣接 Bayer 位相の補間 | `captures/rd8/` |
| RD9 | 整数シフト参照による dither 追従測定 | `captures/rd9/` |
| RD10 | 解析的な連続閾値場（IGN / R2）と lock の厳密性測定 | `captures/rd10/` |

### 11.1 RD9 の測定方法的欠陥（RD10 で是正）

RD9 は「frame 0 の出力」を整数シフトしたものを参照にせず、**効果適用前の生入力**をシフトしたものを参照にしていた。その比較は dither の追従ではなく、効果そのものの強度差を測っていたため、content-lock と screen-lock がほぼ同一（0.149）になっていた。RD10 では参照を「frame 0 の出力の整数シフト」に変更し、参照側の replicate 帯（最大 motions 幅）を内側集計から除外している。

### 11.2 RD10 で追加した測定

- **lock-aligned MAE（整数系列）**: 参照を補間なしで整数シフトし、content-lock の追従を厳密に測る。内側平均 MAE は dither 単独の content-lock で 0.00000000、screen-lock は 0.125〜0.148。
- **lock-aligned MAE（0.5px 系列）**: 参照の resample が dither を low-pass するため blur 限界が不可避。偶数フレームは厳密一致、奇数フレームは参照側の blur が支配するため、判定には使わない。
- **閾値コントラスト比**: オフセット時の閾値 std をゼロオフセット時の std で割った値。Bayer 補間は 0.5px で 0.4728（dither 強度が半減）、IGN / R2 は 1.0000。
- **dither 単独 / full 系的対比**: line gate と texture を外した dither 単独 variant と、screen 固定の hatch texture を含む full variant を同じ表に置き、texture 由来の混在の大きさを可視化している（full の content-lock 内側平均は 0.0175〜0.0227 で、dither 単独の 0 との差は texture 側）。

### 11.3 RD10 で判定していない事項

- screen 固定と content 固定のどちらが視覚的に好ましいたかは、gate 未設定のため判定していない。per-step MAE（画面上の時間変化）は screen 固定が有利、lock-aligned MAE（内容に対する時間変化）は content 固定が有利であり、このトレードオフの最終判断は人手レビューに委ねる。
- IGN / R2 の空間的な見た目（順序 Bayer に対するordered感の違い）は未評価。blind シートは作成済みだが採点は未実施。
- GPU 実装、motion estimation、実アプリ経路、性能予算はいずれも未検証。
