## 1. 目的と対象

### 改善したい見た目

静止画／連番画像を水彩画風へ変換したとき、次を**独立に**制御できる状態を目指す。

- **色のにじみ (bleed):** 色境界付近で顔料が滲み、中間色帯ができること。単なる均一ぼかしではない。
- **紙の凹凸 (paper):** 平坦部に紙目／繊維の質感が乗ること。強すぎると単なるノイズになる。
- **輪郭の溶け方 (edge dissolve):** 輪郭が均一に消えるのではなく、潰れ方に勾配があること。細線が消えるのは失敗例。

「水彩らしさ」の物理的正解を主張しない。評価は再現可能な応答と目視の相対比較であり、実絵画との一致を合格条件にしない。

### 対象素材・操作・レンダー経路

- **素材:** 決定論的に生成する合成 fixture（opaque / alpha 付き）と、ライセンス確認済みの CC0 静止画。連番画像は時間安定性の評価にのみ使う。
- **操作:** オフラインの Python / NumPy / OpenCV による reference model。パラメータは `bleed` / `paper` / `edge` の3成分と、各強度（0 / 中 / 最大）および seed。学習モデルは使わない。
- **経路:** 現時点では**オフライン fixture のみ**を対象とする。Artifact の Composition、Render Queue、preview／final、GPU（D3D12 / Vulkan）は本計画の対象外とし、未検証として記録する。

### 対象外（未検証として明記）

- 学習型 style transfer（ONNX / DirectML）と、実水彩の顔料・流体シミュレーション
- 製品の effect 登録、Inspector プロパティ、既定値、Undo、project 保存／再読込
- 実アプリの画像到達、CPU／GPU parity、backend 差、performance gate
- 動画デコードを含む本格的な時系列対応（連番 8 フレームの安定性評価のみ行う）
- HDR 値域（1.0 超）と OCIO 色空間（現段階は SDR / sRGB のみ）

## 3. 評価素材

### 3.1 決定論的 fixture

seed `20261117`、解像度は 512×320（探索用）と 1536×1024（確認用）の2段。生成手順・hash を manifest に保存する。

| fixture | 目的 | 失敗しやすい例 |
|---|---|---|
| 8 色パッチ + 灰色 ramp | 色混濁・階調つぶれ・banding の測定 | 中間色が単色に潰れる、ramp に段差が出る |
| 細線／エッジチャート（髪・枝・格子） | 輪郭溶解での細線保持 | 細線が消える、線が二重になる（halo） |
| 高コントラスト境界 + 半透明 alpha 境界 | 色滲みと alpha 契約 | 黒／白フリンジ、hidden RGB の漏れ |
| 平坦領域 + 高輝度スポット | 紙目の分散・周波数、クリップ | 紙目が規則的なタイル目になる、高輝度が 1.0 で丸められる |
| 連続フレーム 8 枚（0.5px 平行移動） | 時間安定性 | にじみパターンが揺れる、ghosting |

### 3.2 実写素材

- GlowLab で provenance を確認済みの CC0 画像（neon streets / street light）を再利用候補とする。出所・ライセンス・SHA-256 は `experiments/GlowLab/assets/SOURCES.md` の記録を参照し、本ラボの manifest にもコピーではなく参照情報として記録する。
- 水彩らしさの評価には風景／人物の CC0 素材が別途必要だが、**現時点では未取得**。取得までは実写での品質判定を未検証とする。
- いかなる素材も「無条件に正しい」とは扱わない。撮影条件・色変換の差を記録する。

## 4. 画像条件

| 項目 | 固定／記録する条件 |
|---|---|
| 入力 | linear float（`ImageF32x4_RGBA` 相当）と 8-bit sRGB の2条件を分ける。fixture は linear float で生成し、8-bit は表示用に sRGB OETF で encode |

## 5. 評価項目と合否

各項目に **評価領域／手順／判定者／合格条件／許容差／重大な欠陥** を定義する。数値閾値は baseline 取得後に設定するため、ここでは方法と期限を先に固定する。

### 5.0 閾値の確定手順（開始前の登録）

RD0 で baseline（無処理＋2 control）の full 画像と固定 ROI crop を取得した直後、**候補の最終比較より前に**、実装者とは別のレビュー者が次を数値で事前登録する。

- 登録対象: §5.1〜5.6 の各「合格条件」欄の許容差、および §5.7 の効果固有項目の許容値
- 方法: baseline と control の full／crop を同じ表示条件で見て、領域ごとに「許容できる変化量」を決定する
- 記録: 決定日時、根拠、判定者、変更前後をこの文書へ追記する
- ルール: 閾値未記入の項目は**未評価**とし、R&D 合格に含めない。評価後に閾値を変更する場合は理由・前後・承認者・影響する結果を残し、必要な比較をやり直す

共通の閾値を他 R&D から流用しない。根拠なく PSNR / SSIM の固定値を合格基準にしない。

### 5.1 効果の正しさ

- **評価領域:** 全体、8 色パッチ、灰色 ramp、滲み ROI
- **手順:** (a) `bleed=paper=edge=0` で入力との差分を測る。(b) 各パラメータを 0→中→最大と変えたときの滲み幅・紙目分散・エッジ幅が単調に変化するかを測る。(c) 合成 ground truth の既知領域で応答を再現するかを測る。
- **判定者:** 実装者＋別レビュー者
- **合格条件:** 中立設定で 8-bit は最大チャンネル差 0、float は 1e-6 未満。各パラメータの応答が単調。許容差は §5.0 の手順で固定
- **重大な欠陥:** 中立設定で画像が変わる。パラメータを増やしたのに応答が減る／反転する

### 5.2 画質と細部

- **評価領域:** 全体、細線 ROI、平坦部 ROI、高コントラスト境界 ROI
- **手順:** baseline／control／候補の full と 1:1・拡大 crop を同じ表示条件で blind reviewする。エッジ幅、細線の保持、局地コントラスト、halo、banding、色にじみを記録する
- **判定者:** 別レビュー者（候補名を伏せた状態で判定）
- **合格条件:** 細線 ROI で細線が残存し、平坦部で banding がないこと。許容差は §5.0 で固定
- **重大な欠陥:** 細線の消失、平坦部の可視 banding、境界の白／黒 halo

### 5.3 色と alpha

- **評価領域:** 8 色パッチ、半透明 alpha 境界、透明画素、高輝度スポット
- **手順:** (a) straight と premultiplied の入力で un-premultiply 後の RGB を比較する。(b) 黒／白／中灰の3背景へ合成した後の縁を比較する。(c) クリップ率と非有限値数を測る
- **判定者:** 実装者＋別レビュー者
- **合格条件:** straight／premultiplied 双方で un-premultiply 後 RGB 差が 1e-5 未満。3背景いずれでも縁にフリンジなし。非有限値 0。許容差は §5.0 で固定
- **重大な欠陥:** alpha が小さい領域で RGB が発散する、背景依存の縁色、1.0 超の値が無条件に丸められる（HDR は現段階で対象外だが、丸めが起きる場合は未検証として記録）

### 5.4 時間安定性

- **評価領域:** 固定領域、移動パッチ周辺、滲みパターン
- **手順:** 0.5px 平行移動の 8 フレームで、対応位置を揃えてフレーム間差と時間方向分散を測る。整数移動 fixture では content-locked パターンが共変するかを確認する
- **判定者:** 実装者
- **合格条件:** 整数移動で共変するか、screen-locked の揺れが許容差内。動きに起因する変化を flicker と誤判定しない。許容差は §5.0 で固定
- **重大な欠陥:** 激しい flicker / shimmer、ghosting

### 5.5 経路と解像度

- **評価領域:** 512×320 と 1536×1024 の same-content 画像
- **手順:** 同じ seed・設定で2解像度を生成し、滲み幅・紙目の空間周波数・エッジ幅の傾向を比較する
- **判定者:** 実装者
- **合格条件:** 解像度間で応答の傾向が一致すること。数値許容差は §5.0 で固定
- **対象外:** 製品の preview／final、D3D12／Vulkan 差。これらは**未検証**と明記し、この項目の合格に含めない
- **重大な欠陥:** 低解像度でパターンが破綻する（紙目がエイリアスする等）

### 5.6 性能

- **評価領域:** オフライン reference model の 1 枚あたり実行時間とメモリ
- **手順:** 512×320 と 1536×1024 で warm-up 後に複数回計測し、中央値と最大値を記録する
- **判定者:** 実装者
- **合格条件:** オフライン探索が現実的な時間で回ること。製品の 1080p / 4K gate は未実施として記録する
- **重大な欠陥:** オフライン fixture すら回らないほどの時間／メモリ消費

### 5.7 効果固有の項目

他 R&D の尺度を流用せず、本効果について個別に定義する。

| 成分 | 測定 | 領域 | 備考 |
|---|---|---|---|
| bleed（にじみ） | 色境界からの滲み幅、チャンネル別の広がり、中間色帯の有無 | 8 色パッチの境界、高コントラスト境界 | 滲みが均一ぼかしに退化していないことを確認する |
| paper（紙目） | 平坦部の分散・空間周波数、規則的なタイル目の有無 | 平坦部 ROI | ノイズとの区別を空间周波数で記録する |
| edge（輪郭溶解） | エッジのソフト幅、細線残存率、コントラスト低下 | 細線 ROI | 細線消失を重大欠陥として扱う |

## 5A. RD1 の中間 finding（2026-11-17・判定ではなく観測）

RD1 の候補出力を straight／premultiplied の両 descriptor から生成し、復元 straight RGB の差を記録した（`captures/rd1/metrics_rd1.json` の `descriptor_check`）。

- bleed(bilateral) と paper 単体: 最大差 1.192e-7（float32 丸め）
- edge(softstep) 単体: 0.134、wc_a: 0.138、wc_c: 0.199、wobble を含む wc_b: 0.383

近傍を参照する edge 成分では、「unpremultiply → process → re-premultiply」の順では透明近傍の失われた straight 情報が復元できず、境界で色が変わる。色差で重みを付ける bleed ではこの影響が抑えられた。これは pointwise な色変換で成立する契約を近傍演算へ一般化できないことを示す観測であり、gate 未設定のため合格／不合格の判定ではない。

RD2 では、全成分を premultiplied 空間で処理し alpha と premul RGB に同じ空間変換を適用して最後に一度だけ unpremultiply する v2 を、別 run として比較した（[`captures/rd2/review/DESCRIPTOR_COMPARISON.md`](../captures/rd2/review/DESCRIPTOR_COMPARISON.md)）。straight／premultiplied 入力から復元した straight RGB の最大差は v1 が最大 0.389 だったのに対し、v2 は 12/12 で 0（完全一致）。opaque 36 ケースでは v1 と v2 の RGB 差が 0 で、不透明部の見た目は変わらない。候補 source を変えたため RD1 の blind key／シートは v2 の証跡として使わず、RD2 は独立 run として記録する。これは技術契約の観測であり、品質 gate の合格や製品採用を意味しない。

RD3 で v2 の blind セットを再生成した際、可視領域（alpha > 0.5）は全候補で最大 0.60〜0.70・非有限値 0 だった一方、透明近傍の生 RGB が bleed 成分を含む候補で 1e4〜1e5 オーダーへ発散した（`captures/rd3/metrics_rd3.json` の `descriptive_findings`）。これは **RD2 の「descriptor 差 0」が復元値の健全性を証明しない** ことを示し、両入力が同じように発散していても差は 0 になり得る。目視レビューでは透明画素の RGB を表示結果と混同せず、可視領域のみを対象にする。

RD4 では、bleed も alpha と同じカーネルで処理する v3（joint bilateral と premul／alpha の同一量子化）を別 run として比較した（`captures/rd4/review/COMPARISON_RD4.md`）。alpha fixture 12 ケースで v3 は descriptor 差 0、近透明（0.001 < alpha <= 0.5）の >10 チャンネル 0、非有限値 0 だった。v2 の近透明 >10 は合計 730 チャンネル（最大 258.2）。可視領域の最大値は v1 / v2 / v3 とも 0.60〜0.70 で同程度。不透明 36 ケースでは v1 と v2 の差は 0 だが、v2 と v3 の差は 17 ケースで非ゼロ（最大 0.0118）で、近透明の健全性と不透明部の見た目はトレードオフになり得る。v3 の blind セット（`captures/rd4/blind/`）は独立 run として再生成し、RD1 / RD3 の blind セットは履歴として保持する。これらは記述的観測であり、品質 gate の合格や製品採用を意味しない。

RD5 では v3 を 8 フレーム・0.5px/frame の連番へ適用し、時間安定性とオフライン性能を記録した（`captures/rd5/review/RD5_TABLES.md`）。全候補の per-step global MAE は 0.001018〜0.001403、静止領域 MAE は 0.0008〜0.0016、整数位置再整列 MAE は 0.000001〜0.002316。joint bilateral 単体の実行時間は v2 比で 512×320 が 0.0173s→0.3299s、1536×1024 が 0.1075s→2.7319s（約 19〜25 倍）で、tracemalloc peak は約 2 倍。quantize_gauss を含む候補は v2 とほぼ同じだった。temporal blind セット（`captures/rd5/`）は新たな別 run として生成し、モデル変更はないため RD4 の v3 candidate blind セットの再生成は行わなかった。tracemalloc は Python heap のみで OpenCV のネイティブ確保を含まない。これらも品質 gate の合格や製品性能の証明ではない。

RD6 では、共有重みを保った高速近似 v4（局所エネルギー gate と分離可能 Gaussian、4チャンネルに1つの正規化重み）を別 run として比較した（`captures/rd6/review/RD6_TABLES.md`）。only_bleed の実行時間は v3 比で 512×320 が 0.2876s→0.0221s、1536×1024 が 3.1430s→0.2695s（約 12 倍高速）で、tracemalloc peak は v4 の方が約 13〜14% 大きい。v4 は descriptor 差 0、近透明 >10 チャンネル 0、非有限値 0 を維持し、連番の global MAE も v3 と同程度だった。一方、不透明 36 ケースの v3/v4 最大 RGB 差は bilateral を含む候補で 0.185〜0.598 に達し、他の候補では 0 だった。したがって v4 は高速だが v3 の drop-in 置換ではなく、知覚品質のゲートで別途判断する必要がある。モデルが変わったため v4 の blind セット（`captures/rd6/blind/`）を再生成し、RD4 / RD5 の blind セットは履歴として保持する。gate 未設定のまま、品質合格や製品採用を意味しない。

RD7 では、高速フィルタのパラメータを 80 通り sweep し、v3 出力に対する不透明部の最大 RGB 差を優先して調整した（`captures/rd7/review/RD7_TUNING_TABLE.md`）。最良は k=11 / sigma_space=1.0 / sigma_color=0.6 で、最大差 0.4842、平均 MAE 0.00498 だった。これを固定した v5 を v3 / v4 と同一条件で比較した（`captures/rd7/review/RD7_TABLES.md`）。v5 は descriptor 差 0（12/12）、近透明 >10 チャンネル 0、非有限値 0 を維持し、不透明 v3 差の最大値は 0.484（v4 の 0.598 から低減）だった。only_bleed の 1536×1024 実行時間は v3 2.9049s / v4 0.2076s / v5 0.1915s で v3 比約 15 倍高速。連番 global MAE は wc_a で v3 0.001040 に対し v5 0.001075 と同程度。パラメータ調整でも v3 との最大差は残り、drop-in 置換ではない。モデル変更に伴い v5 の blind セット（`captures/rd7/blind/`）を再生成し、以前の blind セットは履歴として保持する。gate 未設定のまま、品質合格や製品採用を意味しない。

## 6. 画像統計による評価

### 6.1 必須の統計

目的に合う複数統計を選び、全体と欠陥が現れる領域を分けて測る。適用しないものは理由を記録する。

| 測定 | 本 R&D での用途 | 注意点 |
|---|---|---|
| 画素値分布 | min / max / mean / median / 分位点 / ヒストグラム / クリップ率 / 非有限値数 | 平均だけでは局所破綻が隠れる。HDR を 0〜1 に丸めない |
| 参照との差分 | 合成 ground truth に対する MAE / RMSE / 最大値 / 高分位点 / 閾値超過率 / 差分画像 | 実画像には正解がないため、実画像との差分は「参照差分」として適用しない。同じ内容・座標・色・alpha 条件が必要 |
| 構造と細部 | エッジ幅・強度、細線保持、局地コントラスト、周波数分布 | 意図的なぼかしなので入力との差が大きいこと自体は欠陥ではない。SSIM / PSNR は補助指標に留める |
| 色 | 輝度・色差分布、チャンネル偏り | 評価空間（linear / sRGB）と表示変換を明記する |
| 透明度・境界 | alpha 分布、前景／背景漏れ、境界帯誤差、3背景合成後の差 | 透明画素の RGB と表示結果を区別し、alpha が小さい領域の除算条件を明記 |
| ノイズ・時間 | 平坦部の分散・空間分布、固定条件のフレーム間差、時間方向分散・分位点 | 意図的な紙目と flicker を混同しない。必要なら対応位置を揃える |
| 効果固有 | §5.7 の bleed / paper / edge | 他効果の尺度を合格基準に流用しない |

### 6.2 領域

全体に加え、前景／背景／境界／平坦部／高輝度部／細線部から対象に応じて選ぶ。領域の座標・マスク・生成方法・画素数を保存する。平均と併せて分位点・最大値・閾値超過率を確認し、少数の重大な異常が全体集計で埋もれないようにする。

### 6.3 測定結果の記録

入力／参照の識別情報、領域、測定空間・値域、alpha の扱い、指標の定義・単位、集計方法、ツールとバージョン、許容値、結果を残す。差分画像の表示倍率・正規化も記録し、表示用画像と測定用元データを区別する。

統計は目視レビューと組み合わせ、指標の改善だけで視覚品質の向上を断定しない。測定できない項目は未検証として扱う。

## 8. 比較と判定

- 全体画像と評価領域の crop を残し、同じ表示条件で目視確認する。必要なら複数背景への合成も確認する
- 数値比較は目的に合う指標と領域を選び、単位・閾値・集計方法を記録する。PSNR / SSIM や画素差分は補助指標であり、単独で画質全体の合格を証明しない
- 候補と baseline は同じ入力・条件で比較し、品質改善と新たな欠陥、性能・メモリへの影響を併記する。条件が揃わない場合は制約を明記し、同等比較と主張しない
- 欠陥ごとに場所、再現条件、影響、重大度、証拠、対応状況を記録する。重大な欠陥や必須項目の未検証は合格扱いにしない

R&D の完了には、必須評価の結果、合否と根拠、未解決事項、採用／不採用判断、後続実装の受入条件を残す。未達や未検証が残る場合はそのまま明示し、画質達成や製品統合完了と表現しない。**R&D の完了自体は製品実装や新機能追加の承認を意味しない。**
