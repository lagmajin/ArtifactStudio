# Shape Layer Visual Tests

**最終更新:** 2026-10-15

**状態:** 15テスト（27画像ケース）と CTest 登録を追加。ビルド・実行未確認。基準画像は未追加。

シェイプレイヤーの複雑なパスと重なりを、実際の GPU 描画経路で確認する専用テストの配置先。
既存の `ArtifactShapeLayerTest` はパス補間・プロパティ・JSON 復元を担当し、本テストは描画結果を担当する。

## 現在の実装

`ShapeVisualCases.inc` を既存の Render Queue 統合テストに組み込み、アプリ初期化・キュー待機・PNG 読込の既存境界を共有する。独立した CTest 名は `ArtifactShapeVisualTest`、GoogleTest filter は `ShapeVisualTest.*`。新しい exe や製品 API は追加していない。

実装済みの入力ケースは Subtract による穴、Winding / EvenOdd と内周反転、自己交差、ベジェ重複、同一レイヤー内の半透明、レイヤー間の半透明と色の上下反転、密集した輪郭、開閉パスの cap/join、コンテンツ変換とレイヤー変換、content Intersect、Merge Paths operator の5モード。すべて実際の Composition と Shape Layer を作成し、Render Queue の `gpu` backend を要求してフレーム 0 を出力する。初回 content 追加時に作られる既存 primitive の自動スナップショットは明示的に除去する。

PNG は既存 `ARTIFACT_UI_TEST_CAPTURE_ROOT` があればその下の `shape_visual/`、なければ実行時の作業ディレクトリの `shape-visual-output/` に保存する。ファイル名には `_0000.png` が付く。対象の前回画像だけを出力前に削除し、古い画像による誤判定を防ぐ。CTest からは `shape-visual-results.xml` に GoogleTest 結果も保存する。プロジェクトは一時ディレクトリへ隔離する。判定は alpha・色の優先関係・面積のサンプルであり、基準画像比較はまだない。入力配列は既存 Shape Content API の `std::vector` メンバーへ初期値を渡しており、新しい標準コンテナ API は設けていない。

### 未確認・残作業

- ビルド／実行による座標、alpha、出力設定、GPU 使用の実証。現状は GPU を要求する設定であり、実行時 backend の証明はまだない。
- 半透明の色の上下反転はレイヤーの内容交換で検証している。レイヤー順序を変更する編集操作そのものは対象外。
- backend・色空間・AA 設定を含む結果一覧、承認済み基準画像と境界比較。CTest / GoogleTest の結果だけで AA 品質の合格とはしない。

### 高密度・複合ケース

- 20段の Add / Subtract を交互に重ね、各帯と中央の alpha を確認。最内周の除去で中央が変わることを確認し、content snapshot 復元後に20段の判定を繰り返す。
- 三次ベジェによる円を接点近傍で8px重ねる／8px離す組を出力。重なりと透明な隙間を別々に検査する。
- 32枚の半透明レイヤーを重ね、中央の期待 alpha `1 - 0.9^32` と1枚だけを通る領域を比較する。
- 256頂点・128個の尖りを持つ凹ロゼットを描画。負スケール、非等方スケール、回転を加えた画像も検査する。

これらも未実行。固定入力と解析的な alpha／領域判定を設けた段階であり、描画品質や性能の実証結果ではない。

ユーザーからビルドとテスト実行の明示指示を受けた後の単独実行例:

```powershell
ctest --test-dir <build-directory> -C Release -R '^ArtifactShapeVisualTest$' --output-on-failure
```

## 実装する経路

- 実際の `ArtifactShapeLayer` と Composition を生成し、通常の GPU レンダリング経路へ渡す。
- `tests/Artifact/DiligentHeadlessRenderer.hpp` の既存 headless 初期化を調査し、レイヤーの通常描画と接続できるか確認する。直接三角形を描くだけのテストでは代替しない。
- `tests/mask_visual` は成果物の保存・一覧化の参考とする。ただし同テストの CPU マスク合成を流用してシェイプ描画の合否としない。
- 同一レイヤー内のパス処理と、複数レイヤー間の合成を別ケースにする。
- GPU が利用できない場合は実行不能を明示する。ソフト描画への自動切替や空画像の基準化はしない。
- PNG 出力のための readback はテストの確認境界で明示し、製品のフレーム処理へ追加しない。

## 最初の固定ケース

座標系は 512 × 512、背景は透明、時刻はフレーム 0 に固定する。カメラ・色空間・backend・AA 設定を結果に記録する。

| ID | 構成 | 確認する結果 |
|---|---|---|
| compound_hole | 外周と内周の閉パス。内周の向きを反転した組も用意 | 対応する塗り規則に従う穴と内部領域。規則を指定できない場合は現行仕様を先に確認 |
| self_intersection | 自己交差する星形と、交差点を持つ曲線パス | 内外判定、交差点周辺の欠落、破綻した三角形の有無 |
| bezier_overlap | 複数の三次ベジェからなる閉形状を交差させる | 曲線境界の欠け、接点のスパイク、意図しない橋渡しの有無 |
| translucent_contents | 同一レイヤー内で色の異なる半透明コンテンツを重ねる | コンテンツ順序と重複領域の alpha。単一 compound path と混同しない |
| translucent_layers | 別レイヤーの半透明形状を重ね、順序を反転した組も用意 | レイヤー順序、色、alpha。内部の一定色領域を数値確認 |
| dense_strokes | 開パス・閉パス、鋭角・曲線を含む細い輪郭の密集 | join/cap、狭い隙間、AA。現行対応のスタイルのみ使用 |
| transformed_overlap | 移動・回転・非等方スケールした曲線形状の重なり | コンテンツ変換とレイヤー変換の適用順、境界の一致 |
| merge_paths | 同じ入力形状で現行対応する各 Merge Paths モードを適用 | 演算後の内部・外部領域。重なり順による描画との区別 |

## 判定と成果物

- 各ケースの RGBA 画像と、ケース名・backend・描画設定・判定結果を含む結果一覧を保存する。
- 透明領域、穴、一定色の内部領域には解析的に期待値が求まるサンプル点を置く。境界から十分離し、色の作業空間と premultiplied alpha の契約を確認して期待値を定義する。
- AA 境界はサンプル点の厳密比較と分け、承認済みの同一 backend・設定の基準画像と許容差付きで比較する。
- 初回の出力を自動的に正解へ昇格させない。目視レビュー前は基準画像未承認として扱う。
- 複雑な曲線は入力の頂点・接線を固定し、乱数や OS 設定へ依存させない。
- UI を含まない描画テストはロケールに依存させない。独立 viewer にウィジェットを追加してキャプチャする場合は、リポジトリの全 UI ロケール確認規則に従う。
