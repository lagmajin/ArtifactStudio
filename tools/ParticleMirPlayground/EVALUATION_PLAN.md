# Mir 風パーティクルテストプロジェクト 評価計画

対象プロジェクト: `tools/ParticleMirPlayground`（`ArtifactParticleMirPlayground`）

## 1. 目的と対象

- 目的: `ArtifactCore::Procedural3DGenerators` による Mir 風の手続き地形を
  2D は ridge 上の等間隔な Point エミッター位置、3D は
  `EmitterShape::Surface` の放出ソースとして使い、地形表面から煙／火の粉が
  立ち上がる表現が、2D 合成座標系と 3D カメラ系の
  両経路で破綻なく描画されることを検証する。
- 対象レンダ経路:
  - 2D: `ArtifactParticleLayer` → `ArtifactIRenderer` の headless GPU パス
  - 3D: `ArtifactParticle3DLayer` → `ArtifactIRenderer` の 3D カメラ／深度パス
    （地形本体は `drawMesh`、粒子は `draw`）
- 対象外: ソフトレンダラー経路、影／反射の品質、
  パーティクル編集 UI、プロジェクト保存・再読込、共有リポジトリ構成。

## 2. 比較対象

- baseline: 既存の `tools/Particle2DPlayground` / `tools/Particle3DPlayground` の
  同種キャプチャ手順（プレセット単体での描画）。本プロジェクトは地形由来放出を
  追加した派生ケースであり、baseline の物理的な正解_capability ではない。
- 合成 ground truth: なし（本表現に正解画像が存在しない）。
  判定は「破綻の有無」と「応答の連続性」を中心とする。
- 外部参照画像: 他製品のスクリーンショットは物理的な正解として扱わない。
- 前提: 現状の出力が本計画作成時点では未確認である（未確認）。

## 3. 評価素材

- 素材: `Procedural3DGenerators::generateTerrain` の手続き地形（決定的 seed）。
  - 2D 用 seed: 7、3D 用 seed: 11（別 seed で地形形状の差を単独に見積もれるようにした）。
  - 品質: `Procedural3DQuality::Preview`、96×96 グリッド。
- 典型例: フレーム 45 の正面ビュー。
- 失敗しやすい例: 同フレームのカメラ軌道 35 度（裏面／遮蔽の破綻）、
  フレーム 60（寿命差で粒子が消えたケース）、直接シーク（決定性破綻）。
- 出所の記録: 入力はリポジトリ内で手続き生成される（外部素材なし）。
  生成条件は seed・品質・ノイズ設定としてコード内に固定。

## 4. 画像条件

- 解像度: 出力キャプチャ 1920×1080、合成キャンバス 1920×1080。3D は
  3840×2160 で描画してから 1920×1080 にダウンサンプルする。
- 出力: PNG（8bit RGBA、無圧縮）。
- 背景: 単色クリア（0.02, 0.03, 0.05）。
- 乱数: 粒子は `deterministic = true`、`randomSeed = 20261118`。
- 色空間／露出: 線形ワークスペースの headless レンダリング結果をそのまま PNG 化する。
  HDR→sRGB の明示変換は行わない（記録のみ）。
- alpha: 合成空間 Background は不透明。キャンバス外は黒。

## 5. 評価と合否

適用する項目と、合格条件・許容差:

| 項目 | 評価領域 | 手順 | 合格条件 | 許容差 |
|---|---|---|---|---|
| 効果の正しさ | 全体 | フレーム 45 の PNG を生成し、粒子が地形表面から発生しているかをinspection で確認 | 粒子が 1 群以上見え、地形由来の位置から離れない | なし（定性） |
| 描画の非空 | 全体 | `visible_pixels` 計測 | 1 ピクセル以上 | 0 |
| 時間安定性 | 全体 | フレーム 45 と 60 の差分 | 差分ピクセル ≥ 128 | 128 ピクセル |
| カメラ応答 | 全体 | 正面と軌道 35 度の差分 | 差分ピクセル ≥ 128 | 128 ピクセル |
| 決定性 | 全体 | 連続再生のフレーム 45 と直接シークのフレーム 45 | 差分 ≤ 4096 ピクセル、最大チャンネル差 ≤ 24 | 4096 px / 24 |
| 花火・照明の破綻 | 全体（等倍＋拡大） | 機械採点＋視覚採点（下記） | 黒つぶれ・白飛び・矩形欠損・二重像なし | なし（定性） |
| 密度と連続性 | 全体 | 2D ridge 上の 48 Point エミッターによる分布と隙間を視覚採点 | ridge に連続的な分布、明確な大隙間なし | なし（定性） |
| 鉛直分散 | 全体 | 2D 粒子の立ち上がり量 | ridge 上から明確に上方へ分散する | なし（定性） |
| 構図 | 全体 | 3D 正面ビューの地形占有率 | 大きな空き領域を残さない | なし（定性） |
| aliasing | 全体 | 3D 遠景稜線（スーパーサンプリング後） | 軽微な shimmer が見えない | なし（定性） |
| 色と alpha | 全体 | 縁の抜け・前／背景漏れの目視 | 顕著な破綻なし | なし（定性） |
| 経路と解像度 | 全体 | 1920×1080 キャプチャ（3D は 2 倍解像度で描画しダウンサンプル） | 取得成功 | なし |
| 性能 | — | キャプチャ 1 回あたりの処理時間 | 記録のみ（合否判定しない） | なし |

- 閾値（128 px / 4096 px / 24 ch）は本プロジェクト開始前に既定値として固定した。
  baseline 取得後に変更する場合は理由と再比較を残す。
- 判定者: 機械判定（差分・ピクセル計測）と画像認識による視覚採点の両方。
  視覚採点の指摘は「欠陥の所在／再現条件／重大度」として記録する。

## 6. 実行条件

- GPU: 本機の Diligent バックエンド（headless 初期化）。
  実行時にバックエンド名を出力へ記録する。
- 予算: 1 キャプチャあたり 30 秒以内。時間予算は記録のみ。
- 利用できない環境（GPU 初期化失敗、バックエンド不在）は「未検証」と記録し、
  取得済みの他環境の数値を他環境のものとして扱わない。

## 7. 未適用項目の理由

- HDR／高輝度評価: キャプチャは 8bit PNG に Bayer 化されるため、値域外側と
   hibright の HDR 挙動は本計画では未適用（別途未検証として記録）。
- 参照差分（PSNR／SSIM）: 正解画像が無いため、参照差分は未適用。
  代わりに同一条件の参照間（連続再生 vs 直接シーク）の差分のみを契約として使う。
- 環境間比較（Vulkan vs D3D12）: 本プロジェクトは単一バックエンドのみを扱い、
  環境間差の許容範囲は未設定（未検証）。
